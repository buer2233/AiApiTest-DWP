# 接口用例前置数据复用与造数契约

本契约适用于 E9+AI接口自动化测试框架中的所有 E9 接口自动化模块。它约束阶段 ③ 的用例实现和阶段 ④ 的运行期依赖处理，优先保证测试使用当前环境已有业务数据，避免重复造数和不可维护的固定 ID。

## 决策顺序

每条依赖业务数据的用例按以下顺序执行，不能跳步：

1. **定义数据条件**：从功能用例和接口契约提取需要的对象类型、状态、权限、归属角色和必要字段。例如流程模板需可创建、文档需可读取、邮件需满足收发角色权限。
2. **查询当前环境**：优先复用现有接口封装，通过列表、详情或状态接口按业务条件查询。查询结果必须校验状态、权限和关键字段，不得仅因返回非空就使用。
3. **锚定复用对象**：选取满足条件的数据，把返回的业务 ID 和必要上下文传给后续步骤；禁止在代码中写死从其他环境复制的内部 ID。
4. **确认为空**：只有查询结果为空，或结果均不满足条件，才记录“环境数据缺失”，进入造数分析。
5. **反查并尝试造数**：使用 `codebase-memory` MCP 查找对应的创建/保存/发送/提交接口及其依赖，按真实调用顺序执行可行步骤。每步保存脱敏的返回状态和业务 ID，便于后续步骤引用。
6. **判断是否可继续**：造数链路完整且成功时继续编写/执行用例；链路复杂、依赖人工配置或调用失败时阻断该用例的自动化实现，并输出失败说明。

## 造数分析要求

造数前必须回答：

- 目标对象由哪个接口写入，接口 URL、HTTP 方法和必需参数是什么；
- 是否依赖其他对象、角色、权限、密级、模板或系统开关；
- 每一步返回的业务 ID 如何作为下一步入参；
- 数据创建是否幂等、是否有清理接口，以及失败后如何回收。

能拆成多步就必须拆成多步（例如“创建基础对象 → 关联配置 → 提交/发布 → 查询验证”），不能把未尝试的复杂链路直接交给人工。

## 失败报告固定格式

造数无法完成时，回复和功能用例文档中必须包含以下四项：

1. **缺失数据**：对象类型、必要状态/权限/字段和影响的用例；
2. **已做尝试**：查询过的接口/筛选条件、MCP 反查到的候选接口、已经调用的造数步骤；
3. **真实原因**：脱敏后的接口错误、权限/配置限制、依赖对象缺失或无法确认的契约；
4. **人工协助与继续条件**：人工需在哪个页面或配置项创建什么数据，数据满足哪些条件；完成后从哪个步骤继续。

不得编造接口、参数、返回值或错误原因。未确认的内容标记为“待复核”，并阻止将该链路标记为可自动化完成。

## 与运行期降级的关系

`pytest.skip` 只用于代码已正确实现、但运行环境暂时缺少且无法安全创建的数据。skip 消息应包含对象类型、查询结论和人工准备提示；不能用 skip 掩盖尚未查询、尚未反查或尚未尝试的造数工作。造数成功后，应优先复用本次返回的数据完成目标接口断言。
