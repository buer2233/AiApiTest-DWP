# WorkBuddy 项目执行规范（补充规则）

本文件是 `api-test-E9` 项目面向 **WorkBuddy 执行流程**的补充规范，与项目根的
`AGENTS.md`（框架规范）和 `E9_svn_analyse/AGENTS.md`（分析侧规范）互补、互不重叠。

本文件只承载「执行与产物放置约定」，不重复框架内已定义的目录、命名、技术栈要求。

---

## 一、临时文件放置规则

**核心要求：** 会话过程中生成的、系统未明确指定固定落点的**临时/衍生文件**，一律放入
`temp/` 目录，禁止散落在项目根目录或业务目录。

**适用对象（非交付中间产物）：**
- 耗时分析报告、一次性调试/探测脚本、临时导出的 JSON/CSV、调试用 HTML 等；
- 任何「既不属于交付物、也不属于测试数据/运行时产物」的临时文件。

**不适用对象（仍按框架原目录放置，勿打入 temp/）：**
- 测试交付物：`page_api/`、`test_case/`、`tools/`、`test_data/`、`docs/`、`.workbuddy/skills/`；
- 框架规定的运行时/报告产物：`report/`、`runtime/`、`logs/`、`output/`；
- 用户显式指定了路径的文件。

**配套约束：**
- `temp/` 已加入 `.gitignore`，不纳入版本管理，可随时清理，不应被提交。
- 生成临时文件时，若目标位置可用，优先一次性写进 `temp/`，不先落根目录再移动。

---

## 二、规则维护

- 后续新增「仅约束 WorkBuddy 执行行为」的规范时，追加到本文件对应分节，保持单一事实来源。
- 规则变更后，如涉及 git 忽略项，须同步检查 `.gitignore`。
