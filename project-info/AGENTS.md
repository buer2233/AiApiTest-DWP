# project-info/AGENTS.md

本目录是项目说明资料统筹目录，只负责沉淀需求、测试用例、UI 原型、架构图、流程图和交接资料，不存放业务实现代码或运行产物。

## 固定 loop 中的位置

`project-info/` 承载每个需求 loop 的前三个阶段：

- `demand/`：需求分析阶段，输出详细需求说明书和数据库表设计。
- `test_case/`：功能测试用例阶段，输出详细测试用例和验收场景。
- `UI/`：UI 原型图阶段，输出页面原型和交互说明。

后端和前端开发前，必须按根目录的需求分级和裁剪记录找到同一需求命名的适用前置产物；评估为不适用的阶段要有 `N/A + 理由` 记录，不能因目录中没有伪产物而阻塞，也不能无记录跳过适用阶段。

## 子目录职责

| 目录 | 用途 |
| --- | --- |
| `demand/` | 存放需求背景、目标范围、功能设计、验收口径、数据表设计和变更记录。 |
| `test_case/` | 存放功能测试用例、验收用例、异常场景、边界场景和回归测试清单。 |
| `UI/` | 存放 UI 原型图、页面交互说明、组件布局、页面状态和原型生成提示词。 |
| `project_detail/` | 存放项目架构图、流程图、项目说明图片和架构说明文档。 |

## 命名规则

- 同一需求不同阶段产物命名必须一致，仅后缀不同，并能明确区分阶段。
- 推荐格式：`需求名-需求说明.md`、`需求名-测试用例.md`、`需求名-UI原型.md`。
- 架构阶段资料使用英文文件名，当前架构说明以 `project-info/project_detail/project-architecture.md` 为准。

## 通用规则

- 修改本目录前先读取根目录 `AGENTS.md`、当前需求资料和相关子目录 `AGENTS.md`。
- 资料必须使用简体中文编写，专业名词可保留英文原名。
- 文档应保持通用测试平台定位，不写入不可迁移的业务常量、真实地址或敏感配置。
- 需求、测试用例和 UI 原型之间必须能互相追溯，不能出现只有实现没有设计来源的内容。
- 项目资料中引用服务地址时，必须优先引用根目录 `.env` / `.env.example` 的平台绑定主机、公开主机/协议、服务宿主机端口和本机挂载路径变量；Jenkins 公开入口、前端代理和 Playwright 入口应说明由这些公共基础量派生，不得另造重复地址变量。账号、密码、密钥和初始化账号只能说明存在于私有 `.env`、私有环境变量或 Credentials 中，不得写入真实值；数据库名、Cookie 策略等固定值应引用所属模块的代码常量或文档，不得描述为可配置私有项。
- 如需展示本机命令示例，路径使用 `$PROJECT_ROOT`、`PROJECT_WORKSPACE` 或相对路径占位；真实密码、token、Cookie、Jenkins API Token 和生产 URL 不得进入 `project-info/`。
- 若某些私有配置或持久化资源启动后不建议修改，资料必须显式备注原因，例如 MySQL 旧数据卷不会因 `.env` 改密、公开主机/协议/端口变更会影响历史任务链接、`AUTH_TOKEN_SECRET` 轮换会使登录态失效；固定代码常量的变更则必须另走需求 loop 并完成回归。
- Skill 仅按当前会话清单和资料类型选用：复杂关系确需正式图形时可用 `drawio-skill`，确需位图视觉资产时可用 `imagegen`；两者均不能替代需求澄清、文本真源、可追溯关系或阶段验收。
