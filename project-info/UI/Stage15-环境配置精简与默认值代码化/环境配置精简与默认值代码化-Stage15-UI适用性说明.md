## Playwright 关系

Playwright 仍是前端阶段既有 UI 回归和环境验收的执行入口，但本需求不增加新的 UI 场景、选择器、路由断言或截图验收点。前端实现仅可在测试配置层消费新的地址派生结果，例如从统一平台主机、协议和端口计算 `baseURL`；不得把私有账号、密码、token 或配置诊断内容注入页面。

Stage15 的 Playwright 验收重点是：

1. 既有登录、模块通过率、任务和报告入口回归场景仍能通过统一入口访问。
2. `baseURL` 等测试入口不写死个人机器端口或绝对路径，并与 `.env.example` 的公共配置契约一致。
3. 配置漂移或缺失时，失败应发生在配置预检/启动层，不通过新增页面、Toast 或错误 DOM 暴露敏感值。

上述验证属于配置和部署链路回归，不构成 UI 新增需求；实际原始日志和截图按根 `AGENTS.md` 规则仅作为 Jenkins artifact 保存。

## 前端实现范围冻结

允许范围：

- 更新 Vite、Playwright 或相关测试工具读取新配置契约的方式，并保持地址通过公共基础量派生。
- 保留既有页面实现、视觉规范、路由守卫和业务 API 使用方式。
- 为配置契约增加静态检查或测试入口校验，但测试错误只输出键名、行号和类型。

禁止范围：

- 新增配置管理页面、设置菜单、配置表单、配置详情弹窗或任何可见配置字段。
- 在浏览器端暴露私有配置、真实凭据、内部服务名或 `.env` 原始内容。
- 以本需求为由改变既有页面布局、颜色、字体、状态语义、权限边界或交互路径。
- 将配置预检错误、Jenkins 诊断或部署说明复制到产品页面 DOM、截图或 Playwright 断言中。

## 验收口径对应

- `AC1.4`：统一主机、协议和端口派生出的前端代理及 Playwright 入口应保持一致；不增加产品 UI。
