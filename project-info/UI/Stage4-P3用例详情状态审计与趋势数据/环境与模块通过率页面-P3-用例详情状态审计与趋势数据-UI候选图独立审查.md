# 环境与模块通过率页面-P3-用例详情状态审计与趋势数据 UI 候选图独立审查

## 结论：需修正

5 张候选图可以作为正式 UI 原型的素材来源，但不能直接进入前端实现。候选 01、02、03、04 分别覆盖了桌面详情、状态修改、趋势弹窗和移动端详情的主要表达，候选 05 只能提取权限、空态、错误态的局部语义。

当前最大问题是：候选图集合没有完整覆盖 AC8.4 的“无历史趋势空态”；候选 01 的实际画面容易把 P3 用例列表弹窗误做成单条用例详情页；候选 05 明显漂移到“执行列表/趋势看板”页面域，不能作为 `/modules` 路由结构参考。正式 UI 原型必须补充区域语义拆解和前端实现映射后再进入开发。

## 候选图逐张审查

### 候选 01：桌面高密度详情弹窗

- 优点：视觉密度、错误摘要/详情并列、禁用失败重试和桌面大弹窗层级符合 P3 工作台场景；标题包含模块和环境，错误详情面板适合作为 admin 脱敏详情的参考。
- 风险：实际图像把前景做成“单条用例详情”，而不是需求中的“用例详情列表弹窗”；如果照搬会丢失默认失败筛选、组合筛选、分页和多行表格。图中 `/api/v1/users/{id}`、响应体 `id: null`、原始栈和复制按钮可能被误当成冻结字段。
- 不得进入前端 DOM 的内容：示例接口路径、示例用户字段、未脱敏或非 P3 字段的栈内容、`null` 原样展示、导出详情按钮、单条用例详情页式信息架构。正式原型只能保留“列表 + 错误详情预览/展开”的语义。

### 候选 02：管理人员状态修改上下文

- 优点：状态修改确认弹窗最接近 AC5.9/AC10.5，包含当前状态、目标状态、原因必填、512 字限制、审计预览、保存/取消和统计刷新预览。
- 风险：背景页面是“模块列表/模块详情”混合结构，不是 P2/P3 冻结的 `/modules` 当前路由；“上一个/下一个”、附件、关联缺陷、更多操作、新建模块等会诱导新增非 P3 功能。统计刷新只展示模块级变化，未表达环境汇总刷新。
- 不得进入前端 DOM 的内容：独立模块详情页、模块列表新建入口、上一条/下一条、附件/缺陷页签、更多操作菜单、非冻结面包屑。可采纳的是“修改状态弹窗”和“审计预览/统计刷新反馈”组件语义。

### 候选 03：趋势弹窗优先

- 优点：7 天趋势的 SVG 折线、点位 tooltip、文本摘要和同源趋势表格完整，适合落实“不新增图表库”的 Q5 结论；有 7/30 天切换入口和加载失败重新加载按钮。
- 风险：弹窗标题仅为“通过率趋势”，没有把模块名、环境名和窗口写入弹窗标题；图中“返回列表”“操作”不是趋势弹窗必需动作。成功态下同时出现“数据加载失败时可点击重新加载”容易被实现成常驻错误提示。
- 不得进入前端 DOM 的内容：返回列表按钮、非弹窗主流程的操作下拉、常驻错误说明。正式原型应保留 SVG + 表格 + 摘要，并补 30 天和无历史空态。

### 候选 04：移动端详情弹窗

- 优点：390px 视口下采用近全屏 bottom sheet、分段状态、折叠筛选、卡片化用例、长 node id 截断和禁用重试提示，符合 TC-P3-E-007 的移动端方向。
- 风险：顶部“新建模块”和“执行概览”不属于 P3；卡片中默认展示“修改状态”，但没有区分 admin/member；移动端只覆盖用例详情，没有覆盖趋势弹窗移动端表现。触控高度看起来接近要求，但正式实现仍需 Playwright 验证横向溢出不超过 1px。
- 不得进入前端 DOM 的内容：新建模块、执行概览标签、未按权限控制的修改状态按钮、任何仅存在于图片背景中的非 P3 动作。正式原型可采用卡片布局和折叠筛选。

### 候选 05：权限、空态与错误态拼图

- 优点：admin/member 对比、跳过空态、趋势加载失败和无副作用提示表达直观，适合补充权限与异常态设计。
- 风险：4 个面板均漂移到“执行列表/趋势看板”，不是 `/modules` 当前路由内弹窗；“候选 05-1/05-2”等标题属于设计标注，不是产品 UI；member 面板写“只读权限：不显示查看详情”容易违背需求中 member 可查看用例详情和错误摘要的规则。
- 不得进入前端 DOM 的内容：候选标题、说明文字、当前角色调试标识、执行列表路由、趋势看板页面、刷新/筛选/任务字段等非 P3 当前页面结构。只能抽取“member 不显示完整错误详情和状态修改入口”“暂无跳过用例”“趋势数据加载失败 + 重新加载”的状态表达。

## 前端实现风险

- 路由风险：P3 必须全部落在 `/modules` 当前路由内，不能从候选 02/05 派生独立模块详情页、执行列表页或趋势看板页；趋势也只能是模块行触发的弹窗。
- 组件风险：正式组件应拆为 `CaseDetailsDialog`、`CaseStatusFilter`、`CaseResultsTable/CardList`、`CaseErrorDetailPanel`、`CaseStatusUpdateDialog`、`ModuleTrendDialog`，避免把候选 01 的单条详情和候选 02 的模块详情页混成一个巨型组件。
- 弹窗销毁风险：关闭用例详情、状态修改、趋势弹窗后必须销毁内容，不能只是 `v-show` 隐藏，否则 TC-P3-E-006 会在 DOM 中定位到旧用例文本。
- 权限态风险：admin/member 差异必须通过接口 actions 和角色共同控制。member 不渲染完整错误详情入口、不渲染状态修改入口，也不能保留隐藏但可键盘聚焦的按钮。
- 移动端风险：候选 04 可作为详情移动端基准，但缺趋势移动端。正式原型需覆盖 390px 下详情弹窗和趋势弹窗，不出现横向滚动，关键按钮高度不低于 40px。
- 无副作用按钮风险：失败重试、模块重试、Jenkins、Allure、报告入口均不得触发网络写请求；禁用态或后续提示必须可测，不能使用看似可点击的真实按钮。
- 趋势 SVG + 表格风险：不得新增 ECharts 等图表库；SVG 折线和表格必须同源，7/30 天切换只请求对应 `days`，actions 为 false 时按钮禁用且无请求。
- 状态修改风险：候选 02 只画了理想成功路径。正式原型必须覆盖原因空/超长、同状态、归档用例、403、404、422、409 等可恢复错误展示。
- 数据展示风险：字段为空时必须展示 `-` 或空态文本，不得把 `undefined/null`、原始 token/cookie/password、私有 URL 或未脱敏栈展示给用户。

## 必须补入正式 UI 原型的事项

1. 区域语义拆解和前端实现映射：逐一标明候选 01-05 中哪些是当前页面展示、点击后弹窗、设计标注层、废弃不实现。
2. `/modules` 通过率入口说明：点击前不请求 cases，点击后请求 `status=failed&page=1&per_page=20`，标题含模块名和环境名。
3. 用例详情列表态：失败、通过、跳过三种筛选的结果态和空态，包含组合筛选、查询中禁用、重置不影响 `/modules` 全局 query。
4. admin/member 权限映射：admin 可看脱敏完整错误详情和修改状态；member 可看用例详情与摘要，但不显示完整错误详情入口和状态修改入口。
5. 状态修改完整状态集：原因必填、512 字限制、同状态禁用、成功反馈、失败错误、当前列表移除、模块统计和环境汇总刷新、审计写入反馈。
6. AC8.4 无历史趋势空态：`series=[]` 时展示“暂无趋势数据”，不报错，不显示空折线；与候选 05 的加载失败态分开。
7. 近 30 天趋势态：展示 30 天窗口、最多 30 条、按日期升序、SVG 和表格同源。
8. 趋势权限与 actions 控制：`trend_7d/trend_30d=false` 时禁用且点击无请求，true 时只发对应 trend GET。
9. 移动端趋势弹窗：除候选 04 的详情弹窗外，还需补 390px 下趋势 SVG 简化、表格滚动/折叠策略和重载/空态。
10. 禁止进入 DOM 清单：候选标题、候选说明、截图框线、设计备注、执行列表/趋势看板页面、新建模块、上一条/下一条、附件/缺陷、导出详情、真实重试/Jenkins/Allure 动作。
