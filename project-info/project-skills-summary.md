# 当前项目 Skill 使用说明

更新时间：2026-08-04

本文只说明如何选择 Skill，不为开发 loop 增加名称级硬依赖。项目阶段、TDD、审查、证据、安全和容器化门禁以根目录及各子目录 `AGENTS.md` 为准。

## 1. 可用性的唯一事实来源

- 当前会话实际注入的可用 Skills 清单是唯一事实来源；每个新会话都必须重新核对。
- 磁盘存在 `SKILL.md` 不代表当前可调用。未注入会话的目录只能视为残留或待激活能力，不能用于满足流程门禁。
- 仓库文档不长期承诺某个 Skill 一定存在，也不因某个 Skill 下线而跳过需求、测试、实现或验收。

## 2. 选择原则

1. 先识别任务类型和风险，再选择能直接改善结果的最小 Skill 集合。
2. 主人明确点名的 Skill 如在当前会话可用，应先完整读取其说明并按要求执行。
3. 多个 Skill 同时匹配时，只组合职责互补且不会制造冲突的项，并明确使用顺序。
4. Skill 不可用或执行失败时，说明对任务的实际影响，回到 `AGENTS.md` 的行为协议继续，不把工具缺失当作跳过门禁的理由。
5. 需求澄清、TDD、根因排查、独立审查和长任务续接都是工程行为，不依赖特定 Skill 名称。

## 4. 项目常用场景映射

| 场景 | 处理方式 | 可选 Skill |
| --- | --- | --- |
| 需求分析 | 使用需求模板，显式列假设、方案取舍、§0 澄清、架构/API/容器检查 | 无必需 Skill |
| 功能测试设计 | 从 AC 建 RTM，覆盖正常、异常、边界、权限和状态流转 | 无必需 Skill |

| 独立对抗审查 | 启动未参与实现的 review subagent，按严重度报告并复审 | 无必需 Skill |

## 5. 不再由 Skill 承载的关键行为

- **TDD**：先写并运行最小可执行测试，确认有效 RED；最小实现 GREEN；重构并运行相关回归。不得弱化断言或跳过测试换取通过。
- **根因排查**：稳定复现、收集证据、缩小范围、验证根因、最小修复、相关回归。
- **需求深挖**：明确目标、范围、假设和不做事项；关键方案比较取舍；不确定决策写入 §0 并熔断。
- **复杂任务计划**：维护阶段计划和状态；中断恢复先读需求、计划、git 状态、diff、证据和未完成门禁。
- **独立审查**：实现者不自审；独立 reviewer 报告问题；修复后由同一 reviewer 复审至阻断项清零。

## 6. 维护规则

- 新增、删除或重命名 Skill 时，不直接把名称写成全局强制门禁。
- 只有稳定、通用且能降低误触发风险的 Skill 才适合加入场景映射，并始终附带“以当前会话为准”。
- 若 Skill 的重要效果尚未被 `AGENTS.md` 行为规则覆盖，应先补充可验证行为和测试，再调整本说明。
- 历史需求资料中的 Skill 记录是当时执行事实，不做批量追溯改写。
