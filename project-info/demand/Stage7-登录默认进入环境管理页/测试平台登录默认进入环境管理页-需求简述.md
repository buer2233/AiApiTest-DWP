## §1 背景与目标

- **背景**：当前测试平台默认不展示 `/dashboard` 导航入口，但登录成功后仍因前端默认值跳转到 `/dashboard`，造成登录后的首屏落点与平台当前导航不一致。
- **目标**：用户访问 `/login` 并成功登录后，如果 URL 没有显式 `redirect` 查询参数，则进入 `/environments`。
- **成功口径**：登录成功后浏览器地址为 `/environments`；左侧品牌入口和根路径默认入口也指向环境通过率页。

## §2 范围

- **做**：
  - 调整登录页无 `redirect` 时的默认跳转目标为 `/environments`。
  - 调整根路径 `/` 的默认 redirect 为 `/environments`。
  - 保留受保护路由触发登录页时携带的 `redirect` 参数优先级。
  - 更新 Playwright 登录回归断言和验证证据。
- **不做**：
  - 不删除 `/dashboard` 路由，避免破坏已有受保护 URL 回归测试或历史链接。
  - 不新增或修改 DRF API。
  - 不新增 UI 页面、导航项或视觉原型。
  - 不变更权限模型、Cookie 策略、Jenkins 链路或 Allure 报告入口。

## §3 功能与验收标准

### F1 登录成功默认进入环境管理页

- **说明**：当用户从 `/login` 直接登录成功，且当前 URL 没有 `redirect` 参数时，前端应调用 Vue Router 跳转到 `/environments`。
- **验收标准**：
  - `AC-S7-1.1` — Given 用户打开 `/login` When 输入正确账号密码并登录 Then URL 应为 `/environments`。
  - `AC-S7-1.2` — Given 登录成功进入 `/environments` Then 页面应展示环境通过率相关内容，不应依赖 `/dashboard` 首屏。

### F2 显式 redirect 优先级保持不变

- **说明**：用户直接访问受保护 URL 时，路由守卫仍应把原目标写入 `redirect`，登录成功后回到原目标。
- **验收标准**：
  - `AC-S7-2.1` — Given 未登录用户访问 `/dashboard` When 被带到 `/login?redirect=/dashboard` 并登录成功 Then 仍回到 `/dashboard`。
  - `AC-S7-2.2` — Given 未登录用户访问其他受保护路由 When 登录成功 Then 仍回到该受保护路由。

### F3 根路径默认入口同步到环境管理页

- **说明**：访问平台根路径 `/` 时，不应再默认进入隐藏的 `/dashboard`，应进入 `/environments`。
- **验收标准**：
  - `AC-S7-3.1` — Given 已登录用户访问 `/` When 路由完成解析 Then URL 应为 `/environments`。
  - `AC-S7-3.2` — Given 未登录用户访问 `/` When 路由守卫处理 Then 登录页携带的最终目标应指向 `/environments`。

## §4 数据表与更新规则

- 不新增数据表。
- 不修改现有数据表字段、关联关系、更新规则或关键约束。
- 登录态仍由现有 `authToken` Cookie 和 `authStore.ensureCurrentUser()` 处理。

## §5 API 契约冻结

- 不新增后端 API。
- 不修改 `POST /api/v1/auth/login`、`GET /api/v1/auth/me`、`POST /api/v1/auth/logout` 请求/响应字段。
- 前端仍只调用 DRF API，不直接访问 Jenkins、pytest 或 Allure。

## §7 容器化兼容检查

- 本需求不新增环境变量。
- 不写死 API base URL、宿主机端口、真实账号、token、Cookie 或本机路径。
- `/environments` 为前端相对路由，可随 Vite baseURL 和 Docker/Compose 网关部署迁移。

- 前端相关回归输出：至少覆盖 P1 登录路由回归，必要时补 `npm run build`。
- 验收包和 RTM 需引用证据路径。
