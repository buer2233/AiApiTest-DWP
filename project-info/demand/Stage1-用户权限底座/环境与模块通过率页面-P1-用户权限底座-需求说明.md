## §1 需求背景与目标 [必填]

- **背景**：父需求后续 P2-P5 都依赖统一登录态、角色权限和 Cookie 授权门禁。没有 P1 权限底座时，环境通过率、模块通过率、用例详情、Jenkins 任务和重试接口都无法稳定区分管理人员、普通成员和未登录访问。
- **目标**：
  - 建立基于 Cookie `authToken` 的 DRF 鉴权机制。
  - 提供登录、退出登录、当前用户、邀请码注册、用户列表、邀请码管理能力。
  - 保证除登录、注册外的所有平台 API 都必须携带有效授权 Cookie，否则返回 `401 Unauthorized`。
  - 保证未登录用户不能通过 URL 直接访问平台受保护页面，前端必须重定向到登录页或展示 401 受保护路由反馈。
  - 使用已选候选图 5 `Access Split Gate` 作为登录/注册视觉方向，后续 UI 原型和前端实现必须沿用 Claude 风格基线。
- **成功指标 / 价值**：
  - P2-P5 可复用同一个 Cookie 鉴权和角色判断能力，不重复设计权限模型。
  - 管理人员能生成一次性邀请码，受邀用户能完成注册。
  - 未登录 API 访问和未授权 URL 访问均有稳定、可测试的 401 行为。
  - 不提交真实账号、密码、token、Cookie 或生产地址。

## §2 范围 [必填]

- **做（in scope）**：
  - 登录接口：校验账号密码，成功后通过 `Set-Cookie` 写入 `authToken`，返回当前用户摘要。
  - 退出登录接口：清除浏览器侧 `authToken` Cookie。
  - 当前用户接口：读取有效 Cookie 并返回当前用户、角色和权限摘要。
  - 全局 DRF Cookie 鉴权：除登录、注册以外，所有 P1 受保护接口必须鉴权。
  - 邀请码注册：未使用、未过期、未作废的邀请码可注册账号，注册后邀请码进入已使用状态。
  - 邀请码管理：管理人员可生成、查看列表和作废未使用邀请码。
  - 用户列表：管理人员可查看用户列表和角色；普通成员不可访问用户管理接口。
  - 前端登录页、注册页、基础受保护布局、路由守卫、401 未授权反馈。
  - 首个管理人员账号初始化：通过后端初始化命令或种子数据创建，不通过公开注册生成。
  - 选定 UI 候选图 5 作为 Figma 实际原型输入。
- **不做（out of scope）**：
  - 不实现环境通过率、模块通过率、用例详情、趋势图、Jenkins 任务和报告入口。
  - 不实现用户禁用、修改角色、重置密码、找回密码、多租户、项目级权限和细粒度 RBAC。
  - 不实现真实 Figma 在线协作或私有 Figma 链接提交；本阶段只沉淀可追溯 UI 原型资料与导出图。
  - 不记录真实 Cookie、真实 JWT、真实账号密码、真实生产 URL。
  - 不改造 Jenkins、`api-test` 执行协议和 Docker Compose 服务拓扑。

## §4 功能清单与验收标准 [必填 · 核心章节]

### F1 Cookie 登录与退出

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - 用户输入账号和密码后调用登录接口。
  - 登录成功后后端通过 `Set-Cookie` 写入 `authToken`，前端进入受保护平台布局。
  - `authToken` 是后端签发的 JWT 形态令牌，需求文档和实现不得写入真实 token 示例。
  - Cookie 属性由后端统一设置：`HttpOnly`、`SameSite=Lax`、`Path=/`；容器化或 HTTPS 部署时支持通过环境变量启用 `Secure`。
  - 登录失败不写 Cookie，返回明确错误。
  - 退出登录会清除 `authToken` Cookie，之后访问受保护接口返回 401。
- **关联数据表**：`user_account`
- **验收标准（Given-When-Then）**：
  - `P1-AC1.1` — Given 存在启用的用户账号 When 使用正确账号密码调用登录接口 Then 返回 200，响应头包含安全属性正确的 `Set-Cookie: authToken=...`，响应体返回当前用户摘要。
  - `P1-AC1.2` — Given 用户密码错误 When 调用登录接口 Then 返回 401，不设置 `authToken` Cookie，并返回业务码 `invalid_credentials`。
  - `P1-AC1.3` — Given 用户已登录 When 调用退出登录接口 Then 返回 204，并通过 `Set-Cookie` 清除 `authToken`。
  - `P1-AC1.4` — Given 用户退出登录后 When 再调用受保护接口 Then 返回 401 和业务码 `authentication_required`。
- **异常场景**：
  - 请求体缺少账号或密码 → `422 validation_error`。
  - 账号不存在或密码错误 → `401 invalid_credentials`。
  - 停用用户（预留数据状态）尝试登录 → `403 user_inactive`。
- **边界值**：
  - 账号长度 3-64；登录密码必填且最长 64。非空短密码按错误凭据处理，统一返回 `401 invalid_credentials` 和 `账户或密码错误`，不暴露是否命中格式校验。
  - 登录接口不返回密码哈希、JWT 原文以外的敏感解码信息。

### F2 Cookie 鉴权与受保护接口门禁

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - 后端提供统一 Cookie 鉴权类，从请求 Cookie 中读取 `authToken`。
  - 除 `POST /api/v1/auth/login` 和 `POST /api/v1/auth/register` 外，所有 P1 API 都必须通过 Cookie 鉴权。
  - Cookie 缺失、过期、签名无效、用户不存在时均返回 401。
  - 前端路由守卫在进入受保护路由前调用当前用户接口；未登录时阻止直达 URL。
- **关联数据表**：`user_account`
- **验收标准（Given-When-Then）**：
  - `P1-AC2.1` — Given 请求未携带 `authToken` Cookie When 调用任意受保护 P1 API Then 返回 401，业务码为 `authentication_required`。
  - `P1-AC2.2` — Given 请求携带过期或无效 `authToken` Cookie When 调用受保护 API Then 返回 401，业务码为 `invalid_or_expired_token`。
  - `P1-AC2.3` — Given 浏览器未登录 When 直接访问平台受保护 URL Then 前端重定向到登录页或展示 401 受保护路由反馈，不展示平台业务内容。
  - `P1-AC2.4` — Given 用户已登录 When 刷新受保护页面 Then 前端通过当前用户接口恢复登录态并保持页面可访问。
- **异常场景**：
  - Cookie 中存在非平台签发 token → 401。
  - Cookie 中 token 合法但对应用户被删除 → 401。
- **边界值**：
  - 鉴权错误响应不得暴露 JWT 解码失败细节、签名密钥或内部异常栈。

### F3 当前用户与用户列表

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - 当前用户接口返回登录用户的 `id`、`username`、`display_name`、`role`、`permissions`。
  - 用户列表仅管理人员可访问，支持分页和按角色筛选。
  - P1 用户列表只读，不提供禁用、改角色、重置密码。
- **关联数据表**：`user_account`
- **验收标准（Given-When-Then）**：
  - `P1-AC3.1` — Given 用户已登录 When 调用当前用户接口 Then 返回当前用户摘要和权限摘要。
  - `P1-AC3.2` — Given 管理人员已登录 When 调用用户列表接口 Then 返回分页用户列表，包含用户名、展示名、角色、创建时间和最后登录时间。
  - `P1-AC3.3` — Given 普通成员已登录 When 调用用户列表接口 Then 返回 403，业务码为 `admin_required`。
  - `P1-AC3.4` — Given 用户列表存在多条数据 When 使用 `page`、`per_page`、`role` 查询 Then 返回符合筛选条件的分页响应。
- **异常场景**：
  - `per_page` 超过 100 → 返回 `422 validation_error`，提示每页最大 100 条。
- **边界值**：
  - 默认 `page=1`、`per_page=20`。
  - 用户列表不返回密码哈希、Cookie、token 或邀请码明文。

### F4 邀请码注册

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - 系统不开放自由注册。
  - 用户必须输入未使用、未过期、未作废的邀请码才能注册。
  - 注册成功后创建用户并立即将邀请码标记为 `used`，绑定 `used_by` 和 `used_at`。
  - 注册成功不自动登录，用户需要回到登录页使用账号密码登录；这样避免注册接口同时承担 Cookie 签发职责。
  - 注册角色由邀请码目标角色决定，前端不能自行指定角色。
- **关联数据表**：`user_account`、`invitation_code`
- **验收标准（Given-When-Then）**：
  - `P1-AC4.1` — Given 存在未使用且未过期的邀请码 When 用户提交有效注册信息 Then 返回 201，创建用户，并将邀请码状态更新为 `used`。
  - `P1-AC4.2` — Given 邀请码已使用 When 再次用该邀请码注册 Then 返回 422，业务码为 `invalid_invitation_code`，不创建新用户。
  - `P1-AC4.3` — Given 邀请码已过期或已作废 When 用户注册 Then 返回 422，业务码为 `invalid_invitation_code`。
  - `P1-AC4.4` — Given 用户名已存在 When 使用有效邀请码注册 Then 返回 409，业务码为 `username_taken`，邀请码仍保持未使用。
  - `P1-AC4.5` — Given 注册成功 When 查看用户记录 Then 用户角色等于邀请码授权角色。
- **异常场景**：
  - 密码不满足复杂度 → `422 weak_password`。
  - 邀请码格式非法 → `422 invalid_invitation_code`。
- **边界值**：
  - 用户名长度 3-64，只允许字母、数字、下划线、短横线和点。
  - 密码长度 8-64，至少包含字母和数字。

### F5 邀请码管理

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - 仅管理人员可生成邀请码。
  - 生成时选择目标角色 `admin` 或 `member`，默认 7 天过期，可在请求中指定更短或更长的过期时间。
  - 邀请码明文只在创建响应中展示一次；数据库仅保存哈希。
  - 邀请码列表展示状态、目标角色、创建人、使用人、过期时间、创建时间，不展示明文。
  - 管理人员可作废未使用邀请码；已使用邀请码不可作废。
- **关联数据表**：`invitation_code`、`user_account`
- **验收标准（Given-When-Then）**：
  - `P1-AC5.1` — Given 管理人员已登录 When 生成邀请码 Then 返回 201，响应体仅本次包含邀请码明文和记录摘要。
  - `P1-AC5.2` — Given 普通成员已登录 When 生成邀请码 Then 返回 403，业务码为 `admin_required`。
  - `P1-AC5.3` — Given 管理人员查看邀请码列表 When 列表中存在邀请码 Then 响应不包含邀请码明文字段。
  - `P1-AC5.4` — Given 存在未使用邀请码 When 管理人员作废该邀请码 Then 状态变为 `revoked`，后续不能用于注册。
  - `P1-AC5.5` — Given 邀请码已使用 When 管理人员尝试作废 Then 返回 409，业务码为 `invitation_already_used`。
  - `P1-AC5.6` — Given 管理人员生成邀请码未填写过期时间 When 创建成功 Then 默认过期时间为创建时间后 7 天。
- **异常场景**：
  - `role` 非 `admin/member` → `422 validation_error`。
  - 作废不存在的邀请码 → 404。
- **边界值**：
  - 邀请码明文长度建议 24-32 字符，需足够随机。
  - 列表默认 `page=1`、`per_page=20`，最大 100。

### F6 首个管理人员初始化

  - 初始化命令必须幂等：账号不存在时创建，存在时更新基础信息或跳过，不重复创建。
- **关联数据表**：`user_account`
- **验收标准（Given-When-Then）**：
  - `P1-AC6.1` — Given 数据库没有管理人员 When 运行初始化命令 Then 创建一个 `admin` 角色账号。
  - `P1-AC6.2` — Given 已存在同名初始化账号 When 再次运行初始化命令 Then 不创建重复用户。
  - `P1-AC6.3` — Given 初始化环境变量缺失 When 运行初始化命令 Then 命令失败并输出缺失配置说明，不写入半成品用户。
- **异常场景**：
  - 初始化密码不满足复杂度 → 命令失败。
- **边界值**：
  - 初始化命令不得把明文密码写入日志。

## §5 状态机定义 [必填（若存在状态流转）]

### 实体：`invitation_code.status`

| 源状态 | 事件 / 操作 | 目标状态 | 守卫条件 | 副作用 |
| --- | --- | --- | --- | --- |
| `unused` | 用户注册成功 | `used` | 邀请码未过期、未作废、哈希匹配 | 绑定 `used_by`、写入 `used_at`，创建用户 |
| `unused` | 管理人员作废 | `revoked` | 邀请码尚未使用 | 写入 `revoked_by`、`revoked_at` |
| `unused` | 到达过期时间 | `expired` | `expires_at < now()` | 查询时按过期处理；可由定时任务或查询逻辑标记 |
| `used` | 管理人员作废 | 不允许 | 已使用 | 返回 `409 invitation_already_used` |
| `revoked` | 用户注册 | 不允许 | 已作废 | 返回 `422 invalid_invitation_code` |
| `expired` | 用户注册 | 不允许 | 已过期 | 返回 `422 invalid_invitation_code` |

### 实体：`authToken Cookie` 认证状态

| 状态 | 触发条件 | 接口行为 | 前端行为 |
| --- | --- | --- | --- |
| `missing` | 请求未携带 `authToken` | 受保护接口返回 401 | 跳转登录页或展示 401 受保护路由 |
| `invalid` | Cookie 被篡改、签名不匹配或格式错误 | 受保护接口返回 401 | 清理本地登录态并跳转登录页 |
| `expired` | JWT 超过有效期 | 受保护接口返回 401 | 清理本地登录态并提示重新登录 |
| `valid` | Cookie 有效且用户存在 | 接口继续执行权限判断 | 恢复当前用户信息 |

## §7 API 契约 [必填（若涉及接口）· 冻结后前后端共同依据]

### 统一响应与错误格式

- 成功响应使用 `{ "data": ... }`。
- 分页响应使用 `{ "data": [...], "meta": { "total": 0, "page": 1, "per_page": 20, "total_pages": 0 } }`。
- 错误响应使用：

```json
{
  "error": {
    "code": "authentication_required",
    "message": "未登录或登录已过期，请重新登录。",
    "details": []
  }
}
```

### Cookie 鉴权约定

| 项 | 约定 |
| --- | --- |
| Cookie 名 | `authToken` |
| 令牌形态 | 后端签发的 JWT 形态字符串，文档和测试只使用脱敏或测试专用值 |
| Cookie 属性 | `HttpOnly; SameSite=Lax; Path=/`；`Secure` 由环境变量控制 |
| 默认有效期 | 8 小时，后端通过 `AUTH_COOKIE_MAX_AGE_SECONDS` 配置，默认 `28800` |
| 公开接口 | `POST /api/v1/auth/login`、`POST /api/v1/auth/register` |
| 受保护接口 | 除公开接口外，P1 全部接口均需要有效 `authToken` Cookie |

### `POST /api/v1/auth/login`

- **用途 / 权限**：用户登录；公开接口。
- **请求体**：

| 参数 | 位置 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `username` | body | string | 是 | 3-64 字符 | 登录账号 |
| `password` | body | string | 是 | 1-64 字符；非空短密码也按错误凭据处理 | 登录密码 |
| `lang` | body | string | 否 | `zh_CN` / `en_US` | 可选语言偏好，P1 默认 `zh_CN` |

- **成功响应**：`200 OK`，响应头写入 `Set-Cookie: authToken=脱敏测试值; HttpOnly; SameSite=Lax; Path=/; Max-Age=28800`。

```json
{
  "data": {
    "id": 1,
    "username": "admin",
    "display_name": "平台管理员",
    "role": "admin",
    "permissions": ["users:read", "invitations:read", "invitations:create", "invitations:revoke"]
  }
}
```

- **错误码**：

| HTTP | 业务码 | 含义 | 触发条件 |
| --- | --- | --- | --- |
| 401 | `invalid_credentials` | 账户或密码错误 | 用户不存在、密码错误 |
| 403 | `user_inactive` | 用户不可登录 | `is_active=false` |
| 422 | `validation_error` | 参数校验失败 | 缺少账号、密码或格式非法 |

### `POST /api/v1/auth/logout`

- **用途 / 权限**：退出登录；受保护接口。
- **成功响应**：`204 No Content`，响应头清除 `authToken` Cookie。
- **错误码**：未携带有效 Cookie 时返回 `401 authentication_required`。

### `GET /api/v1/auth/me`

- **用途 / 权限**：获取当前登录用户；受保护接口。
- **成功响应**：`200 OK`，返回当前用户摘要和权限摘要。
- **错误码**：未登录、Cookie 无效或过期时返回 `401 authentication_required` 或 `401 invalid_or_expired_token`。

### `POST /api/v1/auth/register`

- **用途 / 权限**：邀请码注册；公开接口，但必须提交有效邀请码。
- **请求体**：

| 参数 | 位置 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `invitation_code` | body | string | 是 | 未使用、未过期、未作废 | 一次性邀请码明文 |
| `username` | body | string | 是 | 3-64 字符，唯一 | 登录账号 |
| `display_name` | body | string | 否 | 1-64 字符 | 展示名称 |
| `password` | body | string | 是 | 8-64 字符，至少字母和数字 | 登录密码 |
| `confirm_password` | body | string | 是 | 与 `password` 一致 | 确认密码 |

- **成功响应**：`201 Created`，不设置登录 Cookie。

```json
{
  "data": {
    "id": 2,
    "username": "member01",
    "display_name": "普通成员",
    "role": "member",
    "created_at": "2026-07-03T10:00:00+08:00"
  }
}
```

- **错误码**：

| HTTP | 业务码 | 含义 | 触发条件 |
| --- | --- | --- | --- |
| 409 | `username_taken` | 用户名已存在 | `username` 唯一约束冲突 |
| 422 | `invalid_invitation_code` | 邀请码不可用 | 不存在、已使用、已过期、已作废 |
| 422 | `password_mismatch` | 两次密码不一致 | `password` 与 `confirm_password` 不一致 |
| 422 | `weak_password` | 密码不满足复杂度 | 长度或复杂度不达标 |
| 422 | `validation_error` | 参数校验失败 | 请求字段缺失或格式非法 |

### `GET /api/v1/users`

- **用途 / 权限**：用户列表；仅管理人员。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `role` | query | string | 否 | `admin` / `member` | 按角色筛选 |
| `page` | query | integer | 否 | >= 1 | 默认 1 |
| `per_page` | query | integer | 否 | 1-100 | 默认 20 |

- **成功响应**：`200 OK`，分页返回用户摘要。
- **错误码**：

| HTTP | 业务码 | 含义 | 触发条件 |
| --- | --- | --- | --- |
| 401 | `authentication_required` | 未登录 | Cookie 缺失或无效 |
| 403 | `admin_required` | 需要管理人员权限 | 普通成员访问 |
| 422 | `validation_error` | 参数校验失败 | 分页或角色参数非法 |

### `POST /api/v1/invitations`

- **用途 / 权限**：生成邀请码；仅管理人员。
- **请求体**：

| 参数 | 位置 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `role` | body | string | 是 | `admin` / `member` | 注册后授予的角色 |
| `expires_at` | body | string | 否 | ISO 8601，未来时间 | 不传则默认 7 天后过期 |

- **成功响应**：`201 Created`，仅本次返回 `plain_code`。

```json
{
  "data": {
    "id": 10,
    "plain_code": "INVITE-EXAMPLE-REDACTED",
    "role": "member",
    "status": "unused",
    "expires_at": "2026-07-10T10:00:00+08:00",
    "created_at": "2026-07-03T10:00:00+08:00"
  }
}
```

- **错误码**：`401 authentication_required`、`403 admin_required`、`422 validation_error`。

### `GET /api/v1/invitations`

- **用途 / 权限**：邀请码列表；仅管理人员。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `status` | query | string | 否 | `unused` / `used` / `revoked` / `expired` | 状态筛选 |
| `role` | query | string | 否 | `admin` / `member` | 角色筛选 |
| `page` / `per_page` | query | integer | 否 | 分页 | 默认 1 / 20 |

- **成功响应**：`200 OK`，不返回 `plain_code`。
- **错误码**：`401 authentication_required`、`403 admin_required`、`422 validation_error`。

### `POST /api/v1/invitations/{invitation_id}/revoke`

- **用途 / 权限**：作废未使用邀请码；仅管理人员。
- **请求参数**：`invitation_id` path 必填。
- **成功响应**：`200 OK`，返回更新后的邀请码摘要。
- **错误码**：

| HTTP | 业务码 | 含义 | 触发条件 |
| --- | --- | --- | --- |
| 401 | `authentication_required` | 未登录 | Cookie 缺失或无效 |
| 403 | `admin_required` | 需要管理人员权限 | 普通成员访问 |
| 404 | `invitation_not_found` | 邀请码不存在 | id 不存在 |
| 409 | `invitation_already_used` | 已使用的邀请码不可作废 | `status=used` |
| 409 | `invitation_not_revocable` | 邀请码不可作废 | 已作废或已过期 |

## §11 非功能要求 [S可简]

- **安全**：
  - 密码必须使用 Django 密码哈希机制，不保存明文。
  - `authToken` Cookie 必须 `HttpOnly`，默认 `SameSite=Lax`。
  - 邀请码数据库只保存哈希，创建响应之外不再展示明文。
  - 所有 401/403 错误都不得暴露 JWT 解析细节、密钥、栈信息或 SQL 错误。
- **性能**：
  - 登录、当前用户接口目标响应时间小于 300ms（不含冷启动）。
  - 用户列表和邀请码列表必须分页，默认 20 条，最大 100 条。
- **可用性**：
  - 登录失败、邀请码无效、注册失败必须给出可恢复提示。
  - 401 状态应引导用户重新登录，不让用户停留在空白页。
- **可观测性**：
  - 登录成功更新 `last_login_at`。
  - 邀请码生成、使用、作废需保留创建人/使用人/作废人和时间。
- **兼容性**：
  - 前端应支持刷新恢复登录态。
  - Cookie 参数通过环境变量适配本地开发和容器化部署。
