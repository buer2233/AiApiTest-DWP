## §1 需求背景与目标 [必填]

- **背景**：P2 已交付环境和模块通过率只读页面，但模块行只能展示聚合快照，无法查看失败用例、无法解释低通过率来源，也不能按管理人员判断把误报用例标记为跳过或通过。父需求要求通过率详情、状态审计和近 7/30 天趋势在 P3 落地，为后续 P5 失败重试和模块重试提供用例级数据底座。
- **目标**：
  - 在 `/modules` 模块通过率页上，点击模块通过率打开用例详情弹窗。
  - 用例详情默认筛选失败状态，支持失败、通过、跳过三种状态筛选。
  - 展示用例名、来源、用例简述、错误类型、断言、执行状态、错误信息摘要和确认结果。
  - 管理人员可手动把当前用例状态修改为失败/通过/跳过，并填写原因，系统记录审计。
  - 普通成员不可修改状态，只能查看允许范围内的用例详情。
  - 提供近 7 天、近 30 天模块趋势弹窗，展示该模块隔离的通过率折线和趋势表格。
- **成功指标 / 价值**：
  - 低通过率模块可以从列表直接追到失败用例明细。
  - 管理人员状态修正后，模块失败数和通过率立即按统一公式刷新并可追溯审计。
  - 趋势弹窗能回答“该模块最近 7/30 天质量是否改善”，且不混入其它模块数据。

## §4 功能清单与验收标准 [必填 · 核心章节]

### F5 通过率详情弹窗与用例状态管理

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - 用户在模块通过率页点击某模块通过率数字或按钮后，打开当前模块的用例详情弹窗。
  - 弹窗默认 `status=failed`，只展示当前失败用例；用户可切换失败、通过、跳过筛选。
  - 查询条件支持用例名、来源 node id、错误类型；重置后恢复默认失败筛选。
  - 表格展示勾选框、用例名、来源、用例简述、错误类型、断言、执行状态、错误信息摘要、确认结果。
  - 长错误信息默认展示脱敏摘要；管理人员可展开脱敏完整详情，普通成员只展示摘要。
  - 管理人员可修改当前用例 `display_status` 为 `failed` / `passed` / `skipped`，必须填写 1-512 字修改原因。
  - 状态修改成功后写入审计，刷新当前弹窗列表、模块快照失败数/通过率和环境快照聚合。
  - 勾选失败重试和一键失败重试按钮本阶段禁用或提示“失败重试功能后续实现”，不发起网络写请求。
- **关联数据表**：`test_case_result`、`case_status_audit`、复用 `module_snapshot`、`environment_snapshot`
- **验收标准（沿用父需求 AC 编号）**：
  - `AC5.1` — Given 模块列表存在某模块 When 用户点击该模块通过率 Then 打开用例详情弹窗，弹窗标题包含模块名称和环境名称。
  - `AC5.2` — Given 弹窗首次打开 When 未手动修改筛选 Then 默认只展示 `failed` 状态用例。
  - `AC5.3` — Given 用户选择“通过”筛选 When 点击查询 Then 只展示 `passed` 状态用例。
  - `AC5.4` — Given 用户选择“跳过”筛选 When 点击查询 Then 只展示 `skipped` 状态用例。
  - `AC5.5` — Given 错误信息包含长堆栈或敏感形态文本 When 页面展示 Then 表格只展示脱敏摘要；管理人员可查看脱敏详情，普通成员不可查看完整详情。
  - `AC5.8` — Given 普通成员打开详情弹窗 When 查看用例行 Then 不展示状态修改入口；若直接调用状态修改 API Then 返回 403。
  - `AC5.9` — Given 管理人员修改当前用例状态并填写原因 When 提交成功 Then 用例状态更新、模块失败数和通过率刷新、环境汇总刷新，并写入一条 `case_status_audit` 记录。
- **异常场景**：
  - `snapshot_id` 不存在或不属于启用环境 → `404 module_snapshot_not_found`。
  - 查询状态不在 `failed/passed/skipped` → `422 validation_error`。
  - 状态修改目标不在 `failed/passed/skipped` → `422 invalid_case_status`。
  - 修改原因为空或超长 → `422 validation_error`。
  - 修改非当前用例结果或已归档结果 → `409 archived_case_result`。
  - 普通成员修改状态 → `403 admin_required`。
- **边界值**：
  - 用例详情分页默认 20 条，上限 100 条。
  - `case_name` 长度上限 256，`node_id` 长度上限 1024，`error_type` 单项长度上限 128。
  - 模块下无当前失败用例 → 弹窗展示空态“暂无失败用例”，不报错。

### F8 近 7 天、近 30 天模块趋势数据

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - 模块行提供“7天趋势”“30天趋势”入口，只打开当前模块的趋势弹窗。
  - 趋势弹窗标题包含模块名称、环境名称和统计窗口。
  - 折线图展示通过率随日期变化，趋势表格展示日期、总用例数、失败数、跳过数、通过率、执行时间、运行类型。
  - 趋势数据来自 `module_run_history`，不由前端从当前快照临时推算。
  - 无历史数据时展示空态，不报前端错误。
- **关联数据表**：`module_run_history`
- **验收标准**：
  - `AC8.1` — Given 模块存在近 7 天历史 When 点击该模块“7天趋势” Then 打开独立弹窗并展示该模块 7 天内通过率表格和折线趋势。
  - `AC8.2` — Given 模块存在近 30 天历史 When 点击该模块“30天趋势” Then 打开独立弹窗并展示该模块 30 天内通过率表格和折线趋势。
  - `AC8.3` — Given 模块 A 和模块 B 都有历史数据 When 打开模块 A 趋势弹窗 Then 不展示模块 B 的历史数据。
  - `AC8.4` — Given 模块没有对应窗口历史数据 When 打开趋势弹窗 Then 展示空态，不报前端错误。
- **异常场景**：
  - `days` 非 7 或 30 → `422 validation_error`。
  - `snapshot_id` 不存在 → `404 module_snapshot_not_found`。
- **边界值**：
  - 返回数据按 `run_date` 升序，最多 30 条。
  - 当某天无运行记录，不强行补 0 点；前端只绘制后端返回点。

### F10.5 状态审计

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - 每次管理人员手动修改用例状态时，系统记录操作人、原状态、新状态、原因、修改时间、关联用例、关联模块和关联环境。
  - 审计记录只追加，不物理删除，不允许通过本阶段 API 修改。
  - 状态修改 API 响应返回本次审计记录 ID 和修改后统计摘要，供前端提示。
- **关联数据表**：`case_status_audit`
- **验收标准**：
  - `AC10.5` — Given 管理人员修改用例状态 When 提交成功 Then 系统生成包含操作者、原状态、新状态、原因、时间、用例和模块信息的审计记录。
- **异常场景**：
  - 未登录用户调用状态修改 → `401 authentication_required`。
  - 普通成员调用状态修改 → `403 admin_required`。

## §5 状态机定义 [必填]

### 实体：`test_case_result.display_status`

- **状态全集**：
  - `failed`：当前失败，展示在失败筛选中，计入失败数，降低通过率。
  - `passed`：当前通过，展示在通过筛选中，不计入失败数。
  - `skipped`：当前跳过，展示在跳过筛选中，不计入失败数，但计入总数。
  - `archived`：历史归档状态，P3 不对外筛选和手动设置，预留给 P5 模块重试归档旧结果。

| 源状态 | 事件 / 操作 | 目标状态 | 守卫条件 | 副作用 |
| --- | --- | --- | --- | --- |
| `failed` | 管理人员手动修改 | `passed` | 当前用例、原因必填 | 失败数减 1，通过数加 1，重算模块/环境通过率，写审计 |
| `failed` | 管理人员手动修改 | `skipped` | 当前用例、原因必填 | 失败数减 1，跳过数加 1，重算模块/环境通过率，写审计 |
| `passed` | 管理人员手动修改 | `failed` | 当前用例、原因必填 | 失败数加 1，通过数减 1，重算模块/环境通过率，写审计 |
| `passed` | 管理人员手动修改 | `skipped` | 当前用例、原因必填 | 通过数减 1，跳过数加 1，通过率不因跳过降低，写审计 |
| `skipped` | 管理人员手动修改 | `failed` | 当前用例、原因必填 | 失败数加 1，跳过数减 1，重算模块/环境通过率，写审计 |
| `skipped` | 管理人员手动修改 | `passed` | 当前用例、原因必填 | 跳过数减 1，通过数加 1，写审计 |
| 任一当前状态 | 管理人员提交相同状态 | 不允许 | 当前状态未变化 | 返回 `409 case_status_unchanged`，不写审计、不刷新统计 |
| `archived` | 任意手动修改 | 不允许 | 非当前用例 | 返回 `409 archived_case_result`，不写统计 |

### 实体：`case_status_audit`

- 审计记录只追加，不更新、不删除。
- 审计记录由 `PATCH /case-results/{id}/status` 成功提交产生。

## §6 数据表设计 [必填]

> P3 表均归属 `metrics` app，使用 Django migration 落库。正式字段类型可在后端 TDD 阶段微调，但不得改变本节语义和 API 契约。

### 表 `test_case_result`

- **用途**：保存模块当前和历史用例结果，为用例详情弹窗、状态筛选、后续失败重试提供数据源。
- **写入策略**：P3 由 dev-only seed 幂等写入；状态修改只更新当前记录的 `display_status`，不物理删除。P5 模块重试时可将旧记录改为 `archived` 并写入新当前记录。
- **关键约束**：建议 `environment_id + module_id + node_id + is_current` 在 `is_current=true` 时唯一，避免同一模块当前结果重复。

## §7 API 契约 [必填 · 冻结后前后端共同依据]

> 前缀 `/api/v1`，无尾斜杠；成功 `{data,meta?}`，错误 `{error:{code,message,details}}`；查询接口登录可读，状态修改仅管理人员可执行。每接口必须配 drf-spectacular `@extend_schema` 和 Swagger 回归测试。

### `GET /api/v1/module-snapshots/{snapshot_id}/cases`

- **用途 / 权限**：获取模块用例详情；登录用户可读，默认筛选失败。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `snapshot_id` | path | integer | 是 | 当前快照存在 | 模块快照 ID |
| `status` | query | string | 否 | `failed/passed/skipped` | 默认 `failed` |
| `case_name` | query | string | 否 | 长度 <= 256 | 用例名模糊筛选 |
| `node_id` | query | string | 否 | 长度 <= 1024 | 用例来源模糊筛选 |
| `error_type` | query | string | 否 | 长度 <= 128 | 错误类型筛选 |
| `page` | query | integer | 否 | >=1 | 页码 |
| `per_page` | query | integer | 否 | 1-100 | 每页条数 |

- **成功响应**：`200 OK`

```json
{
  "data": [
    {
      "id": 501,
      "node_id": "test_case/test_gbif_case/test_species.py::test_search_species",
      "case_name": "test_search_species",
      "case_summary": "物种名称搜索返回 200",
      "error_type": "AssertionError",
      "assertion_text": "expected status_code == 200",
      "execution_status": "failed",
      "display_status": "failed",
      "error_message_summary": "AssertionError: expected 200, got 500",
      "error_message_detail": "仅管理人员返回脱敏详情；普通成员为 null",
      "confirmation_result": "人工确认中",
      "actions": {
        "can_update_status": true,
        "can_retry": false
      }
    }
  ],
  "meta": {
    "total": 1,
    "page": 1,
    "per_page": 20,
    "total_pages": 1
  }
}
```

- **错误码**：

| HTTP | 业务码 | 含义 | 触发条件 |
| --- | --- | --- | --- |
| 401 | `authentication_required` | 未登录 | Cookie 缺失或无效 |
| 404 | `module_snapshot_not_found` | 模块快照不存在 | `snapshot_id` 不存在 |
| 422 | `validation_error` | 参数非法 | 状态、分页或筛选字段非法 |

- **分页 / 筛选 / 排序**：后端分页；默认排序 `display_status`、`occurred_at desc`、`id`。

### `PATCH /api/v1/case-results/{case_result_id}/status`

- **用途 / 权限**：管理人员手动修改当前用例展示状态；仅 `admin` 可执行。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `case_result_id` | path | integer | 是 | 当前用例结果存在 | 用例结果 ID |

- **请求体**：

| 字段 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- |
| `display_status` | string | 是 | `failed/passed/skipped` | 目标展示状态 |
| `reason` | string | 是 | 1-512 字 | 修改原因 |

- **成功响应**：`200 OK`

```json
{
  "data": {
    "case_result": {
      "id": 501,
      "display_status": "skipped",
      "confirmation_result": "人工标记跳过"
    },
    "module_summary": {
      "snapshot_id": 101,
      "total_count": 100,
      "failed_count": 3,
      "passed_count": 94,
      "skipped_count": 3,
      "pass_rate": "0.970000"
    },
    "environment_summary": {
      "environment_id": 1,
      "total_count": 200,
      "failed_count": 7,
      "pass_rate": "0.965000"
    },
    "audit_id": 9001
  }
}
```

- **错误码**：

| HTTP | 业务码 | 含义 | 触发条件 |
| --- | --- | --- | --- |
| 401 | `authentication_required` | 未登录 | Cookie 缺失或无效 |
| 403 | `admin_required` | 仅管理人员可修改用例状态 | 普通成员调用 |
| 404 | `case_result_not_found` | 用例结果不存在 | ID 不存在 |
| 409 | `archived_case_result` | 已归档结果不可修改 | `is_current=false` 或 `display_status=archived` |
| 409 | `case_status_unchanged` | 用例状态未变化 | 目标状态与当前状态一致 |
| 422 | `invalid_case_status` | 目标状态非法 | 非 `failed/passed/skipped` |
| 422 | `validation_error` | 修改原因非法 | 原因为空或超长 |

- **关键状态流转 / 幂等**：状态修改必须在事务内完成用例状态、模块快照、环境快照和审计写入。失败时不得产生半成品审计。

## §11 非功能要求 [S可简]

- **性能**：用例详情后端分页，默认每页 20，上限 100；趋势最多返回 30 条；用例筛选字段建索引。
- **安全**：错误详情展示前做脱敏，屏蔽 token、cookie、Authorization、密码、私有 URL 形态文本；状态修改必须鉴权和审计。
- **可用性**：弹窗加载、空态、错误态均可恢复；状态修改成功后给出明确反馈并刷新当前上下文。
- **一致性**：通过率公式继续沿用 P2 `(total_count - failed_count) / total_count`；跳过计入总数但不计失败。
- **可观测性**：状态修改通过 `case_status_audit` 保留人、事、时、原因；seed 命令输出创建/更新数量。
- **兼容性**：P3 不破坏 P2 `/modules` 现有筛选、分页、移动端卡片和后置能力禁用断言。
