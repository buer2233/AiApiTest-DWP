## 1. 拆分规则

- 每个阶段都按 M 档处理，执行完整 loop：需求说明、功能测试用例、UI 原型、后端 TDD、前端 TDD、独立审查、验收包、独立 commit 和 push。
- 阶段产物必须使用统一命名：`环境与模块通过率页面-P{序号}-{阶段名}-{产物后缀}.md`。
- 父需求中的 API、表结构和 AC 编号保持不变；阶段文档只做范围切片，不重新定义父需求。
- 阶段只能消费前序阶段已冻结 API、数据库迁移和页面能力，不允许后序阶段反向修改前序阶段验收口径。
- Jenkins 执行链路放到后置阶段，前序阶段可以使用种子数据或同步结果数据完成只读页面验收。
- 容器化兼容检查每阶段都必须执行，禁止新增本机绝对路径、宿主机固定端口、真实凭据或不可迁移手工配置。

## 3. P1 用户权限底座

### 范围

- 登录接口、当前用户接口、基础鉴权中间件。
- 邀请码注册：生成、列表、作废、一次性使用。
- 两类角色：管理人员、普通成员。
- 前端登录页、注册页、用户管理入口、邀请码管理入口。

### 不做事项

- 不实现环境/模块通过率页面。
- 不实现用例状态修改，因为该能力依赖 P3 的 `test_case_result`。
- 不实现 Jenkins 任务和重试。

### 数据表

- `user_account`
- `invitation_code`

- `POST /api/v1/auth/register`
- `GET /api/v1/users`

- `POST /api/v1/invitations/{invitation_id}/revoke`

## 5. P3 用例详情、状态审计与趋势数据

### 范围

- 模块通过率点击后打开用例详情弹窗。
- 默认筛选失败状态，支持失败、通过、跳过筛选。
- 详情弹窗字段：勾选框、用例名、用例简述、错误类型、断言、执行状态、错误信息、确认结果。
- 管理人员可手动修改当前用例状态，并记录审计。
- 普通成员不可手动修改用例状态。
- 近 7 天、近 30 天模块趋势弹窗，包含表格和折线图。

### 不做事项

- 不执行勾选失败重试和一键失败重试，只预留禁用或后置提示。
- 不实现 Jenkins 任务弹窗。

### 数据表

- `test_case_result`
- `module_run_history`
- `case_status_audit`

### API 范围

- `GET /api/v1/module-snapshots/{snapshot_id}/cases`
- `PATCH /api/v1/case-results/{case_result_id}/status`
- `GET /api/v1/module-snapshots/{snapshot_id}/trend`

## 6. P4 Jenkins 任务与报告入口

### 范围

- Jenkins 任务记录表和模块执行锁。
- 当前模块今天的 Jenkins 任务弹窗。
- 字段：`id(job_id)`、任务名、测试环境 URL、状态、操作。
- “取消任务”调用 Jenkins 取消接口，并将状态流转到 `canceling` / `canceled`。
- “查看报告”跳转 Allure 报告链接。
- “查看Jenkins任务”跳转 Jenkins job 页面。

### 不做事项

- 不触发每日全量执行。
- 不触发失败重试或模块重试。
- 不解析测试结果，不更新模块快照。

### 数据表

- `jenkins_task`
- `module_execution_lock`

### API 范围

- `GET /api/v1/module-snapshots/{snapshot_id}/jenkins-tasks`
- `POST /api/v1/jenkins-tasks/{task_id}/cancel`
- `GET /api/v1/jenkins-tasks`

## 7. P5 Jenkins 执行闭环与重试能力

### 范围

- Jenkins 每天凌晨 2 点全量执行。
- DRF 同步全量执行结果，更新环境快照、模块快照、用例结果和历史数据。
- 模块行“一键失败重试”。
- 详情弹窗勾选失败用例后“失败重试”。
- 详情弹窗“一键失败重试”。
- 模块重试。
- 同一测试环境同一模块执行互斥，冲突提示“已有用例重试，无法执行！”。
- 失败重试不更新模块“日期”和“执行时间”；模块重试更新模块“日期”和“执行时间”。

### 不做事项

- 不扩展 AI 分析报告真实生成能力。
- 不实现旧平台截图中未明确的其它操作。
- 不引入除管理人员、普通成员之外的新角色。

### 数据表

- 复用并完善 `test_run`
- 复用并完善 `jenkins_task`
- 复用并完善 `module_execution_lock`
- 复用并完善 `environment_snapshot`
- 复用并完善 `module_snapshot`
- 复用并完善 `test_case_result`
- 复用并完善 `module_run_history`

### API 范围

- `POST /api/v1/module-snapshots/{snapshot_id}/failed-case-retries`
- `POST /api/v1/module-snapshots/{snapshot_id}/module-reruns`
- Jenkins 定时触发与同步回调接口，具体路径在 P5 API 契约冻结时补充。

## 8. 阶段依赖与门禁

| 门禁 | 通过条件 | 阻塞后续 |
| --- | --- | --- |
| P1 权限门禁 | 登录、邀请码注册、角色判断、管理人员后台可用 | P2-P5 所有前端页面和受控接口 |
| P2 数据门禁 | 环境、模块、快照和只读页面可用，模块通过率公式正确 | P3 用例详情和趋势；P4/P5 Jenkins 任务关联模块 |
| P3 用例数据门禁 | 当前用例结果、状态筛选、手动改状态和趋势数据可用 | P5 勾选失败重试和结果同步 |
| P4 Jenkins 任务门禁 | 任务弹窗、取消任务、报告链接、Jenkins 链接和锁表可用 | P5 执行互斥、失败重试和模块重试 |
| P5 执行闭环门禁 | Jenkins 触发、结果同步、锁释放、报告入口和统计更新全部通过 | 父需求最终验收 |

## 9. 回归策略

- 每阶段都必须回归前序阶段核心路径，不能只测当前阶段新增能力。
- 后端每阶段保留 pytest 实际运行输出和覆盖率数据。
- 前端每阶段保留 Playwright 运行结果和关键页面截图。
- 每阶段验收包必须列出本阶段 AC 覆盖、前序阶段回归结果、容器化兼容检查和残留风险。
- P5 完成后执行父需求总验收，按父需求 AC1.1-AC10.5 全量回归。
