## §1 需求背景与目标

- **背景**：现行规则把一批已经从当前会话能力清单移除的 Skill 写成必须或推荐依赖，导致 agent 启动即遇到不可满足约束，也让质量要求错误地依赖 Skill 名称。
- **目标**：把 Skill 从流程硬依赖降为按任务匹配的可选增强，同时把需求分析、测试设计、TDD、系统化诊断、前后端工程约束和独立审查等关键行为直接写入规则。
- **成功指标**：生效中的治理文档不再引用已移除 Skill；五阶段 loop、四项固定检查点、RED-GREEN-REFACTOR、证据归档和独立对抗审查均有明确规则与静态门禁。

## §2 范围

- **做**：重构根目录及模块 `AGENTS.md` 的 Skill 策略；同步 `project-info/project-skills-summary.md`、`docs/自主开发流水线.md`；新增静态门禁测试；形成 RTM、审查记录和验收包。
- **不做**：不修改产品功能、数据库、DRF API、Vue 页面、Jenkins 执行协议、Docker Compose；不安装或卸载本机 Skill；不改写历史需求记录中的当时事实。

## §3 用户角色与权限矩阵

| 角色 | 可执行操作 | 禁止操作 | 数据可见范围 |
| --- | --- | --- | --- |
| 主人 | 冻结需求、裁决熔断、最终验收 | 无 | 全部仓库资料 |
| 主 agent | 按动态清单选择 Skill、执行 loop、汇总证据 | 把未加载 Skill 当作可用能力、弱化门禁 | 当前任务范围 |

## §4 功能清单与验收标准

### F1 动态 Skill 选择

- **AC1.1**：Given agent 读取生效中的治理文档，When 检索已删除的 Skill 名称，Then 不存在名称级强制或推荐依赖。
- **AC1.2**：Given 新会话提供不同的 Skill 清单，When agent 开始任务，Then 只按当前会话清单和任务匹配度选用 Skill，且 Skill 不可用不会跳过质量要求。
- **AC1.3**：Given 磁盘存在未注入会话的 Skill 目录，When agent 盘点能力，Then 明确其不是当前可调用 Skill。

### F2 保持开发 loop 与 TDD

- **AC2.1**：Given 任一新需求，When 进入开发流程，Then 仍按需求分级、需求分析、功能测试用例、UI 原型、后端、前端的既有 loop 推进。
- **AC2.2**：Given 代码或可执行脚本行为发生变化，When 开始实现，Then 先产生能因缺失行为失败的自动化测试，再做最小实现，最后重构和回归。
- **AC2.3**：Given 任一档位，When 评估裁剪，Then 需求澄清、架构影响、API 契约和容器兼容检查不可裁剪。

### F3 用行为规则承接关键 Skill 效果

- **AC3.1**：Given agent 处理需求、测试、后端、前端或故障，When 对应专用 Skill 不存在，Then 仍能从 `AGENTS.md` 得到明确的分析、设计、测试、实现和诊断检查项。
- **AC3.2**：Given 前端或 UI 任务需要设计增强，When 当前会话提供 `ui-ux-pro-max`、`design-system` 或 `imagegen`，Then 可按任务匹配选用，但不得替代 UI 映射、可访问性、响应式和验收门禁。
- **AC3.3**：Given Python 测试或图形任务，When当前会话提供 `python-testing` 或 `drawio-skill`，Then 可按任务匹配选用且不设置全局强制调用。

### F4 独立审查与可验证治理

- **AC4.1**：Given 实现阶段完成，When 进入验收前，Then 由未参与实现的独立 review subagent 审查；审查不依赖任何特定 Skill 名称。
- **AC4.2**：Given 治理文档后续发生漂移，When 执行静态测试，Then 已删除 Skill 回流、loop/TDD/审查门禁缺失会使测试失败。
- **AC4.3**：Given 审查发现问题，When 主 agent 修复后，Then 同一 review subagent 复审至无阻断问题。

## §5 状态机定义

本需求不新增业务状态机。流程状态沿用：`草稿 -> 已冻结 -> RED -> GREEN -> REFACTOR -> 独立审查 -> 验收 -> 提交并推送`；任一门禁失败回到对应阶段修复。

## §11 非功能要求

- 规则应短于现有 Skill 清单式说明，避免同一约束在多处以不同 Skill 名重复表达。
- 当前会话能力变化时，不需要再次修改根规则才能继续执行。
- 历史需求档案保留当时事实，不因本次治理重构产生大面积无关 diff。
