## §1 需求背景与目标 [必填]

- **背景**：父需求已冻结并拆分为 P1-P5。P1 已交付用户权限底座。P2 要在其上建立“测试数据底座”，让平台第一次拥有可展示的环境与模块通过率数据，为 P3（用例详情/趋势）、P4（Jenkins 任务）、P5（执行闭环）提供数据模型和只读页面基础。
- **目标**：
  - 从 `api-test/utils/package_module.yaml` 幂等同步模块元数据到 `test_module`。
  - 配置唯一初始测试环境“模拟测试环境”（基础地址 `https://api.gbif.org`）。
  - 建立环境快照、模块快照数据模型与三个只读查询 API。
  - 交付环境通过率页面、模块通过率页面的**只读**展示，通过率公式统一为 `(总用例数 - 失败用例数) / 总用例数`。
  - 保留“生成环境报告”按钮，仅占位提示“AI 分析报告功能后续实现”。
- **成功指标 / 价值**：
  - 登录用户可在环境维度查看整体通过率概况，在模块维度查看每个模块最新快照的日期、负责人、通过率、执行时间。
  - 模块列表支持后端分页、筛选、排序，不一次性拉全量。
  - 数据模型与只读契约冻结，P3-P5 可无缝在其上叠加。

## §2 范围 [必填]

- **做（in scope）**：
  - `metrics` app：`test_environment`、`test_module`、`test_run`、`environment_snapshot`、`module_snapshot` 五张表及迁移。
  - `sync_modules` 管理命令：F1 模块元数据幂等同步（生产可用）。
  - `seed_environment` 管理命令：幂等写入“模拟测试环境”基础配置。
  - `seed_demo_metrics` 管理命令：**dev-only** 演示快照数据，供只读页面验收，非生产逻辑。
  - 三个只读 API：`GET /test-environments`、`GET /test-environments/{id}/summary`、`GET /module-snapshots`。
  - 公共分页/错误封装提取到公共模块，`accounts` 同步切换（等价重构）。
  - 前端环境通过率页 `/environments`、模块通过率页 `/modules`，含加载/空/错误态、后端分页筛选、独立导航菜单。
  - “生成环境报告”按钮占位。
- **不做（out of scope）**：
  - 不实现用例详情弹窗、状态筛选、手动改状态、状态审计（P3）。
  - 不实现近 7/30 天趋势弹窗（P3）。
  - 不触发 Jenkins、不实现失败重试/模块重试/执行锁/取消任务（P4/P5）。
  - 不新建 `test_case_result` / `module_run_history` / `jenkins_task` / `module_execution_lock` / `case_status_audit` 表（后置阶段）。
  - 不实现 AC4.3、AC4.4（失败重试/模块重试对“日期/执行时间”的更新规则，属 P5）。
  - 不实现真实 AI 分析报告生成。

## §4 功能清单与验收标准 [必填 · 核心章节]

### F1 模块元数据读取与同步

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - `sync_modules` 命令读取 `api-test/utils/package_module.yaml`，按 `package_name`（YAML 顶层 key）幂等 upsert 到 `test_module`。
  - 字段映射：顶层 key → `package_name`；`module_name` → `module_name`；`module_dev` → `module_dev`；`module_test` → `module_test`；`case_path` 按约定推导为 `test_case/{package_name}`。
  - 缺失必填字段（`module_name`/`module_dev`/`module_test` 任一缺失）时，跳过该条并记录同步失败原因，不生成字段不完整的模块记录。
  - 模块负责人变化时，下次同步更新为最新值。
- **关联数据表**：`test_module`
- **验收标准（沿用父需求 AC 编号）**：
  - `AC1.1` — Given `package_module.yaml` 存在模块配置 When 执行 `sync_modules` Then 每个顶层 key 生成或更新一条 `is_active=true` 的模块记录。
  - `AC1.2` — Given YAML 中某模块 `module_dev`/`module_test` 变化 When 再次 `sync_modules` Then 模块通过率页展示最新负责人。
  - `AC1.3` — Given YAML 某模块缺失必填字段 When 同步 Then 记录同步失败原因（命令输出/日志），不生成该字段不完整的记录。
- **边界 / 幂等**：
  - 重复执行 `sync_modules` 结果一致（幂等），不产生重复记录。
  - YAML 中被移除的模块：本阶段保留旧记录（不物理删除），后续阶段如需下线再评估 `is_active` 策略。

### F3 环境通过率主页面（只读）

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - 提供测试环境下拉，初始仅一个“模拟测试环境”（`https://api.gbif.org`）。
  - 选择环境后展示该环境最新有效快照（`environment_snapshot`）：环境名、开始时间、结束时间、环境地址、通过率、运行时间。
  - 环境地址来自后端授权响应，不在前端硬编码。
  - 保留“生成环境报告”按钮，点击仅提示“AI 分析报告功能后续实现”，不触发 Jenkins、不写数据、不建任务。
- **关联数据表**：`test_environment`、`environment_snapshot`
- **验收标准**：
  - `AC3.1` — Given 已配置“模拟测试环境” When 打开环境通过率页 Then 下拉包含“模拟测试环境”。
  - `AC3.2` — Given 选择“模拟测试环境” When 查询环境汇总 Then 展示环境、开始时间、结束时间、环境地址、通过率、运行时间和模块通过率入口。
  - `AC3.3` — Given 环境暂无快照 When 选择环境 Then 展示空状态，不报前端错误。
  - `AC3.4` — Given 环境地址属于配置项 When 页面展示 Then 地址来自后端响应，不在前端硬编码。
  - `AC3.5` — Given 点击“生成环境报告” When 本期未实现 AI 报告 Then 提示“AI 分析报告功能后续实现”，不触发任何 Jenkins 任务。

### F4 模块通过率主页面（只读）

- **能做什么 / 做到什么程度 / 满足什么要求**：
  - 按模块展示 `module_snapshot`：日期（`completed_at`）、用例包名、模块名称、模块开发、模块测试、通过率、执行时间（`duration_seconds`）。
  - 通过率公式固定 `(total_count - failed_count) / total_count`；失败数只统计 `failed`；跳过不计入失败但计入总数（P2 展示层遵循此口径，快照统计字段由种子/后续同步保证）。
  - 列表支持后端分页、按模块名称/包名/模块测试/通过率上限筛选、按通过率与日期排序。
  - 本阶段“日期/执行时间”来自种子快照；失败重试/模块重试对这两个字段的更新规则（AC4.3/AC4.4）属 P5，不在本阶段实现。
- **关联数据表**：`module_snapshot`、`test_module`
- **验收标准**：
  - `AC4.1` — Given 模块存在最新快照 When 打开模块通过率页 Then 展示日期、用例包名、模块名称、模块开发、模块测试、通过率和执行时间。
  - `AC4.2` — Given 模块 `total_count=100`、`failed_count=4` When 页面展示 Then 通过率为 96.00%。
- **边界**：
  - 无模块快照 → 空态，不报错。
  - `total_count=0` → 通过率展示为 0% 或“—”，不得除零报错。
  - 分页参数越界（page<1 / per_page>100）→ 后端返回 422（复用 P1 分页校验）。
- **本阶段不实现**：`AC4.3`（失败重试不更新日期/执行时间）、`AC4.4`（模块重试更新日期/执行时间）→ P5。

## §5 状态机定义 [必填]

- `test_case_result.display_status` 状态机属 P3，本阶段不涉及。

## §7 API 契约 [必填 · 冻结后前后端共同依据]

> 前缀 `/api/v1`，无尾斜杠（`APPEND_SLASH=False`）；成功 `{data,meta?}`，错误 `{error:{code,message,details}}`；均需登录（`CookieJWTAuthentication`），未登录 401；列表后端分页筛选排序；每接口配 drf-spectacular `@extend_schema`。

### `GET /api/v1/test-environments`
- **用途/权限**：可用测试环境列表；登录用户可读。
- **请求参数**：`is_active`（query, boolean, 否）。
- **成功响应**：`200`，`{"data":[{"id","env_key","env_name","base_url"}]}`。

### `GET /api/v1/test-environments/{environment_id}/summary`
- **用途/权限**：环境通过率汇总；登录用户可读。
- **请求参数**：`environment_id`（path, int, 是）。
- **成功响应**：`200`，`{"data":{"environment":{id,env_name,base_url},"started_at","finished_at","duration_seconds","total_count","failed_count","passed_count","skipped_count","pass_rate","actions":{"generate_report":true}}}`；无快照时统计字段为 0/null，前端展示空态。
- **错误码**：`404 environment_not_found`（环境不存在）。

### `GET /api/v1/module-snapshots`
- **用途/权限**：模块通过率列表；登录用户可读。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `environment_id` | query | int | 是 | 存在且启用 | 测试环境 |
| `module_test` | query | string | 否 | ≤128 | 模块测试精确/模糊 |
| `module_name` | query | string | 否 | ≤128 | 模块名称模糊 |
| `package_name` | query | string | 否 | ≤128 | 用例包名模糊 |
| `pass_rate_lte` | query | number | 否 | 0-100 | 通过率≤百分比 |
| `page` | query | int | 否 | ≥1 | 页码 |
| `per_page` | query | int | 否 | 1-100 | 每页条数 |
| `sort` | query | string | 否 | 白名单 | 默认 `pass_rate,completed_at` |

- **成功响应**：`200`，`{"data":[{id,completed_at,package_name,module_name,module_dev,module_test,total_count,failed_count,pass_rate,duration_seconds,actions:{...}}],"meta":{total,page,per_page,total_pages}}`。P2 `actions` 中 `failed_rerun/module_rerun/trend_7d/trend_30d/jenkins_tasks` 统一返回 `false`（后置阶段开放）。
- **错误码**：`422 validation_error`（环境无效/分页越界/排序字段非白名单）。
- **分页/筛选/排序**：后端分页，复用公共分页封装；排序白名单 `pass_rate`、`completed_at`、`failed_count`。

## §11 非功能要求 [S可简]

- **性能**：模块列表后端分页，默认每页 20、上限 100；查询走索引（`pass_rate`、`failed_count`、`completed_at`）。
- **安全**：只读接口需登录；环境地址后端授权返回；不泄露敏感配置。
- **可用性**：无数据时展示空态不报错；接口错误前端可重试。
- **一致性**：通过率统一公式 `(total-failed)/total`；`total=0` 不除零。
- **可观测性**：`sync_modules`/`seed_*` 命令输出可读的执行摘要与失败原因。
