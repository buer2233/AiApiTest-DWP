### Issues

#### Critical (Must Fix)

- 无。

#### Important (Should Fix)

1. **非启用环境的用例详情未按契约返回 404。**
   需求明确 `snapshot_id` 不存在或不属于启用环境时返回 `404 module_snapshot_not_found`（需求说明 `:102`），但 `ModuleSnapshotCasesView` 只执行 `filter(id=snapshot_id)`，没有约束 `environment__is_active=True`（`back-end/metrics/views.py:298`-`:300`）。这会让登录用户读取已停用环境的用例详情，破坏环境启用状态隔离。`ModuleSnapshotTrendView` 同样只按 `id` 查 snapshot（`back-end/metrics/views.py:453`-`:455`），建议一起对齐启用环境口径。

2. **脱敏规则未覆盖冻结需求要求的私有 URL/地址形态，且测试未验证完整敏感集合。**
   冻结需求要求错误展示前屏蔽 token、cookie、Authorization、密码、私有 URL 形态文本（需求说明 `:463`；功能测试用例 `:131`-`:133`）。当前 `SENSITIVE_PATTERNS` 只覆盖 Authorization Bearer、password、cookie、token（`back-end/metrics/serializers.py:11`-`:16`），没有处理内网 URL、IP、带凭据 URL 等地址形态；测试只断言某个 token 字符串未出现在 admin detail（`back-end/tests/test_metrics_case_details_api.py:31`-`:33`），没有覆盖 cookie/password/private URL。

3. **`test_case_result` 缺少当前结果唯一约束，无法从数据库层防止同一模块当前用例重复。**
   冻结需求建议对当前结果建立 `environment_id + module_id + node_id + is_current` 唯一约束（需求说明 `:185`），实际模型只声明两个普通索引（`back-end/metrics/models.py:160`-`:165`），迁移也只添加普通索引（迁移 `:86`-`:93`）。一旦后续真实同步或手工导入产生重复当前记录，cases 接口会返回重复用例，状态修改也无法保证针对唯一当前结果。

4. **状态机和事务测试没有覆盖冻结用例声明的全部真实行为。**
   功能测试用例要求覆盖 `failed -> passed`、`passed -> failed`、`passed -> skipped`、`skipped -> failed`、`skipped -> passed` 等状态流转（功能测试用例 `:187`-`:215`），以及状态修改异常时事务回滚（`:261`-`:267`）。当前 pytest 只验证了 `failed -> skipped` 成功路径（`back-end/tests/test_metrics_case_status_api.py:25`-`:50`），缺少其余流转和回滚用例，无法证明 `status_delta` 在全部边界下都真实刷新 `passed/skipped/failed` 计数。

5. **seed 幂等和 OpenAPI 回归测试断言偏弱，未完全验证规格门禁。**
   seed 用例名称是“不堆重复数据”，但只断言当前用例和趋势记录数量 `>=` 下限（`back-end/tests/test_metrics_commands.py:133`-`:138`），重复插入时仍可能通过。OpenAPI 用例要求参数、请求体、200/401/403/404/409/422 响应描述完整（功能测试用例 `:398`-`:404`），当前测试只检查路径、少量参数和少数描述字符串（`back-end/tests/test_metrics_swagger_docs.py:37`-`:52`），没有断言业务错误码如 `admin_required`、`case_status_unchanged`、`invalid_case_status` 是否进入 schema 描述或示例。

#### Minor (Nice to Have)

1. **seed 命令文案仍停留在 P2。**
   `seed_demo_metrics` 的 help 和 `summary_json.stage` 仍写 P2（`back-end/metrics/management/commands/seed_demo_metrics.py:20`、`:43`）。不影响功能，但会给 P3 验收和后续排障造成阶段识别噪音。

2. **`module_run_history` 的唯一约束包含可空 `source_run`，后续真实同步需谨慎。**
   模型允许 `source_run=null`（`back-end/metrics/models.py:177`），唯一约束又包含该字段（`:190`-`:196`）。在 MySQL 下唯一索引通常允许多条 `NULL` 组合并存；P3 seed 当前传入非空 run，问题不立即触发，但 P5 若允许空 run upsert，可能削弱幂等性。
