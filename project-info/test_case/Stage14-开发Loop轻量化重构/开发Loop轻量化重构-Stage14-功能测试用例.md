# 开发 Loop 轻量化重构 Stage14 功能测试用例

## 模块 A：Skill 治理

### TC-ST14-SKILL-001（P0）生效规则无失效 Skill 引用

- **关联需求**：AC1.1、AC1.2
- **前置条件**：已定义生效治理文档集合与失效 Skill 名单。
- **步骤**：逐文件扫描根和嵌套 `AGENTS.md`、自主流水线说明、Skill 总结。
- **预期**：失效 Skill 名称均不存在；规则声明以当前会话清单为准，且 Skill 不承载质量门禁。

### TC-ST14-SKILL-002（P1）磁盘残留不冒充可用能力

- **关联需求**：AC1.3
- **步骤**：比较会话注入清单与磁盘 `SKILL.md`。
- **预期**：盘点资料明确区分“当前可用”和“仅磁盘存在”。

### TC-ST14-SKILL-003（P1）可用 Skill 按任务匹配

- **关联需求**：AC3.2、AC3.3
- **步骤**：检查治理说明中的当前可用 Skill 场景索引。
- **预期**：设计、位图、图表、Python 测试等场景存在可选建议，没有全局强制组合。

## 模块 B：Loop 与 TDD 回归

### TC-ST14-LOOP-001（P0）五阶段 loop 保持

- **关联需求**：AC2.1
- **步骤**：检查根规则和自主流水线的阶段顺序、依赖、命名和自动衔接。
- **预期**：需求、功能测试、UI、后端、前端阶段保持；分级规则未删除。

### TC-ST14-TDD-001（P0）TDD 不依赖 Skill

- **关联需求**：AC2.2
- **步骤**：检查根、`api-test`、后端、前端、Jenkins 规则。
- **预期**：均以可观察失败测试开始，按 RED -> GREEN -> REFACTOR 执行，并保留回归证据。

### TC-ST14-GATE-001（P0）不可裁剪门禁保持

- **关联需求**：AC2.3
- **步骤**：检查根规则的需求澄清、架构影响、API 契约、容器兼容门禁。
- **预期**：任何档位均不可裁剪。

## 模块 C：行为规则与独立审查

### TC-ST14-BEHAVIOR-001（P0）关键能力行为化

- **关联需求**：AC3.1
- **步骤**：检查需求、测试、UI、后端和前端模块规则。
- **预期**：各模块均包含不依赖 Skill 的输入、检查、实现、异常和验收要求。

### TC-ST14-REVIEW-001（P0）独立对抗审查不依赖 Skill

- **关联需求**：AC4.1、AC4.3
- **步骤**：检查根、后端、前端和自主流水线规则，并核对本需求审查记录。
- **预期**：实现者不自审；独立 review subagent 给出结论，问题修复后复审。

### TC-ST14-STATIC-001（P0）治理漂移自动失败

- **关联需求**：AC4.2
- **步骤**：运行 Stage14 静态测试。
- **预期**：失效名称回流或 loop/TDD/审查关键标记缺失时失败；最终版本通过。

## 回归范围

- Stage13 文档与环境唯一入口静态门禁。
- 全部 Stage14 治理静态门禁。
- `git diff --check`、所有 `CLAUDE.md` 单行引用检查、敏感信息模式检查。
