## 1. 功能测试用例

### TC-P1-F-001 登录成功并恢复当前用户

- **关联需求**：P1-AC1.1、P1-AC2.4、P1-AC3.1
- **测试目标**：验证正确账号密码可登录，后端设置 `authToken` Cookie，刷新后可通过当前用户接口恢复登录态。
- **优先级**：P0
- **前置条件**：
  - 数据库存在启用的 `admin_user`，角色为 `admin`。
  - 登录密码为测试专用密码，不是真实生产密码。
- **测试数据**：
  - `username=admin_user`
  - `password=TestPass123`
- **操作步骤**：
  1. 调用 `POST /api/v1/auth/login` 提交账号和密码。
  2. 检查响应状态、响应体和 `Set-Cookie`。
  3. 携带返回的 `authToken` Cookie 调用 `GET /api/v1/auth/me`。
  4. 前端刷新受保护页面，触发当前用户接口恢复登录态。
- **预期结果**：
  - 登录接口返回 200。
  - 响应头包含 `authToken` Cookie，具备 `HttpOnly`、`SameSite=Lax`、`Path=/` 和有效 `Max-Age`。
  - 登录响应和当前用户接口均返回 `id`、`username`、`display_name`、`role`、`permissions`。
  - 刷新后前端仍处于已登录状态。
- **备注**：接口测试使用脱敏或测试专用 Cookie，不记录真实 token。

### TC-P1-F-002 退出登录后 Cookie 失效

- **关联需求**：P1-AC1.3、P1-AC1.4
- **测试目标**：验证退出登录能清除 Cookie，退出后不能继续访问受保护接口。
- **优先级**：P0
- **前置条件**：用户已通过 TC-P1-F-001 登录。
- **测试数据**：已登录用户的测试 Cookie。
- **操作步骤**：
  1. 携带有效 Cookie 调用 `POST /api/v1/auth/logout`。
  2. 检查响应状态和清理 Cookie 的 `Set-Cookie`。
  3. 使用退出前 Cookie 再调用 `GET /api/v1/auth/me`。
- **预期结果**：
  - 退出接口返回 204。
  - 响应头清除 `authToken` Cookie。
  - 退出后访问当前用户接口返回 401，业务码为 `authentication_required` 或 `invalid_or_expired_token`。

### TC-P1-F-003 管理人员查看用户列表并筛选分页

- **关联需求**：P1-AC3.2、P1-AC3.4
- **测试目标**：验证管理人员可以查看用户列表，并按角色筛选、分页。
- **优先级**：P0
- **前置条件**：
  - 管理人员已登录。
  - 数据库存在至少 1 个 `admin` 和 2 个 `member` 用户。
- **测试数据**：
  - `role=member`
  - `page=1`
  - `per_page=20`
- **操作步骤**：
  1. 携带管理人员 Cookie 调用 `GET /api/v1/users?role=member&page=1&per_page=20`。
  2. 检查响应状态、`data`、`meta`。
  3. 检查每条用户记录字段。
- **预期结果**：
  - 返回 200。
  - `data` 只包含 `member` 用户。
  - `meta` 包含 `total`、`page`、`per_page`、`total_pages`。
  - 用户记录不包含 `password_hash`、Cookie、token 或邀请码明文。

## 2. 异常与权限测试用例

### TC-P1-ERR-001 登录账户或密码错误

- **关联需求**：P1-AC1.2
- **测试目标**：验证错误凭据不能登录，短密码也不能暴露为参数校验错误，且不设置 Cookie。
- **优先级**：P0
- **前置条件**：存在启用用户。
- **测试数据**：正确账号 + 错误密码；正确账号 + 短错误密码 `222`。
- **操作步骤**：
  1. 调用登录接口提交错误密码。
  2. 调用登录接口提交短错误密码 `222`。
  3. 检查响应状态、错误码和响应头。
- **预期结果**：
  - 返回 401，业务码 `invalid_credentials`。
  - 错误文案统一为 `账户或密码错误`，不得返回 `请求参数校验失败`。
  - 不设置 `authToken` Cookie。
  - 错误响应不暴露账号是否存在的细节。

### TC-P1-ERR-002 缺失、过期或无效 Cookie 访问受保护接口

- **关联需求**：P1-AC2.1、P1-AC2.2
- **测试目标**：验证所有受保护接口都执行 Cookie 鉴权。
- **优先级**：P0
- **前置条件**：存在受保护接口 `/api/v1/auth/me`、`/api/v1/users`、`/api/v1/invitations`。
- **测试数据**：
  - 无 Cookie。
  - 伪造 Cookie：`authToken=invalid-test-token`。
  - 过期测试 Cookie。
- **操作步骤**：
  1. 分别使用三类 Cookie 状态调用受保护接口。
  2. 检查响应状态和业务码。
- **预期结果**：
  - 无 Cookie 返回 `401 authentication_required`。
  - 伪造或过期 Cookie 返回 `401 invalid_or_expired_token`。
  - 响应不泄露 JWT 解析细节、签名密钥或栈信息。

## 3. 边界测试用例

### TC-P1-E-001 用户名、密码和确认密码边界

- **关联需求**：P1-AC4.1、P1-AC4.4
- **测试目标**：验证注册字段边界和密码一致性。
- **优先级**：P1
- **前置条件**：存在有效邀请码。
- **测试数据**：
  - 用户名 2 字符、3 字符、64 字符、65 字符。
  - 用户名包含中文：`中文账号`。
  - 密码 7 字符、8 字符、64 字符、65 字符。
  - `password` 与 `confirm_password` 同为 65 字符。
  - `password` 与 `confirm_password` 不一致。
  - `password` 与 `confirm_password` 不一致且密码本身也不满足复杂度。
- **操作步骤**：
  1. 使用上述边界数据分别调用注册接口。
  2. 检查响应业务码。
- **预期结果**：
  - 合法边界值可注册。
  - 非法边界值返回 422。
  - 中文账号返回 `422 invalid_username`，错误文案为 `账号只能包含字母、数字、下划线、短横线和点。`，且前端应本地拦截不提交注册接口。
  - 弱密码返回 `422 weak_password`，错误文案包含 `密码需 8-64 位，至少包含字母和数字`，并明确 `长度不足 8 位`、`缺少字母` 或 `缺少数字` 等具体原因。
  - 密码不一致返回 `422 password_mismatch`；当密码不一致与弱密码同时存在时，优先提示 `两次输入的密码不一致。`，前端不提交注册接口。
  - 两次密码相同但长度超过 64 位时返回 `422 weak_password`，提示 `长度超过 64 位`，不得误报为密码不一致。
  - 无效注册不消耗邀请码。

## 4. 状态流转测试用例

### TC-P1-ST-001 邀请码状态流转

- **关联需求**：P1-AC4.1、P1-AC4.2、P1-AC4.3、P1-AC5.4、P1-AC5.5
- **测试目标**：验证邀请码 `unused -> used/revoked/expired` 及非法迁移。
- **优先级**：P0
- **前置条件**：管理人员已登录，存在多个未使用邀请码。
- **测试数据**：未使用邀请码 A、B、C。
- **操作步骤**：
  1. 使用邀请码 A 注册用户。
  2. 作废邀请码 B。
  3. 将邀请码 C 调整为过期测试状态。
  4. 分别尝试复用 A、注册 B、注册 C、作废 A。
- **预期结果**：
  - A 注册后状态为 `used`，不可复用且不可作废。
  - B 作废后状态为 `revoked`，不可注册。
  - C 过期后按 `expired` 处理，不能注册。

### TC-P1-ST-002 Cookie 鉴权状态流转

- **关联需求**：P1-AC2.1、P1-AC2.2、P1-AC2.4、P1-AC1.3、P1-AC1.4
- **测试目标**：验证 Cookie 从缺失、有效、退出、过期/无效的状态流转。
- **优先级**：P0
- **前置条件**：存在启用用户。
- **测试数据**：测试用户账号、有效 Cookie、过期 Cookie、伪造 Cookie。
- **操作步骤**：
  1. 无 Cookie 调用当前用户接口。
  2. 登录获取有效 Cookie。
  3. 携带有效 Cookie 调用当前用户接口。
  4. 调用退出登录接口。
  5. 使用退出后 Cookie、过期 Cookie、伪造 Cookie 访问当前用户接口。
- **预期结果**：
  - 无 Cookie 返回 401。
  - 有效 Cookie 返回当前用户。
  - 退出后 Cookie 不再可用。
  - 过期或伪造 Cookie 返回 401。

## 5. UI 与路由测试用例

### TC-P1-UI-001 未登录直达受保护 URL

- **关联需求**：P1-AC2.3
- **测试目标**：验证前端路由守卫阻止未登录用户直接进入平台受保护页面。
- **优先级**：P0
- **前置条件**：浏览器无 `authToken` Cookie。
- **测试数据**：受保护 URL，例如 `/dashboard` 或后续平台首页路由。
- **操作步骤**：
  1. 在无 Cookie 浏览器上下文打开受保护 URL。
  2. 观察页面跳转和接口请求。
- **预期结果**：
  - 页面跳转到登录页或展示 401 受保护路由反馈。
