## 3. F3 Jenkins Job binding 初始化与触发可用性

### TC-S8-3.1-001 初始化失败重试和模块重试 binding `[接口]`
- **关联 AC**：AC-S8-3.1
- **优先级**：P0
- **前置条件**：存在启用环境和启用模块，环境变量包含 `JENKINS_FAILED_RERUN_JOB_NAME`、`JENKINS_MODULE_RERUN_JOB_NAME`。
- **步骤**：执行 `python manage.py sync_jenkins_job_bindings`。
- **预期结果**：
  - 每个启用环境和启用模块均存在 active 的 `failed_rerun`、`module_rerun` binding。
  - 命令输出创建、更新、跳过数量。
  - 不输出 Jenkins 账号、API Token 等敏感值。

### TC-S8-3.2-001 初始化 Daily Job binding `[接口]`
- **关联 AC**：AC-S8-3.2
- **优先级**：P0
- **前置条件**：环境变量包含 `JENKINS_DAILY_FULL_JOB_PREFIX`。
- **步骤**：执行 `sync_jenkins_job_bindings`。
- **预期结果**：每个启用环境和启用模块存在 active 的 `daily_full` binding，Job 名按 `{JENKINS_DAILY_FULL_JOB_PREFIX}-{module.package_name}` 生成，例如 `AiApiTest-DWP-Daily-Full-Module-Species`。

### TC-S8-3.2-002 初始化命令幂等 `[接口]`
- **关联 AC**：AC-S8-3.1、AC-S8-3.2
- **优先级**：P1
- **步骤**：连续执行两次 `sync_jenkins_job_bindings`。
- **预期结果**：第二次只更新或跳过既有记录，不重复创建同一 `environment_id + module_id + task_type`。

### TC-S8-3.2-003 Job 名环境变量为空时跳过对应类型 `[接口]`
- **关联 AC**：AC-S8-3.1、AC-S8-3.2
- **优先级**：P1
- **步骤**：清空 `JENKINS_DAILY_FULL_JOB_PREFIX` 或任一重试 Job 名变量后执行 `sync_jenkins_job_bindings`。
- **预期结果**：
  - 命令跳过对应 task type 并输出跳过原因。
  - 不创建空 `job_full_name` 的 binding。
  - 其它已配置 task type 仍可正常 upsert。

### TC-S8-3.3-001 Job binding 存在时触发 Jenkins 构建 `[接口] [UI]`
- **关联 AC**：AC-S8-3.3
- **优先级**：P0
- **前置条件**：当前用户为管理人员，模块存在失败数且对应 binding active。
- **步骤**：
  1. 点击模块列表行“一键失败重试”。
  2. 点击模块重试并在确认弹窗中确认。
- **预期结果**：
  - 后端返回 202。
  - 创建 `queued` Jenkins task。
  - Jenkins client 收到对应 `job_full_name` 和参数。
  - 失败重试前端提示“开始执行失败重试”并刷新任务状态。
  - 模块重试确认后前端提示任务已创建并刷新任务状态。

### TC-S8-3.4-001 Job binding 缺失返回可读错误 `[接口] [UI]`
- **关联 AC**：AC-S8-3.4
- **优先级**：P0
- **步骤**：禁用或删除当前模块 binding 后触发失败重试。
- **预期结果**：
  - 后端返回 422 `jenkins_job_not_configured`。
  - 不创建 Jenkins task，不创建执行锁。
  - 前端展示禁用原因或错误提示。

### TC-S8-3.5-001 普通成员不可触发重试 `[接口] [UI]`
- **关联 AC**：AC-S8-3.5
- **优先级**：P0
- **步骤**：普通成员打开 `/modules` 并尝试触发失败重试或模块重试。
- **预期结果**：
  - 触发按钮不可用或后端返回 403。
  - 前端不允许绕过禁用态发起 Jenkins 构建。

### TC-S8-3.6-001 同模块活跃重试任务由后端兜底互斥 `[接口] [UI]`
- **关联 AC**：AC-S8-3.3
- **优先级**：P0
- **前置条件**：当前模块已存在 `queued`、`running` 或 `canceling` 状态的 `failed_rerun` / `module_rerun` Jenkins task。
- **步骤**：
  1. 在模块列表点击“一键失败重试”。
  2. 再点击“模块重试”并确认。
- **预期结果**：
  - 后端返回 409 `module_execution_locked`。
  - 错误文案为 `已经有正在的本模块用例`。
  - 前端按钮仍可点击，不在该业务场景提前禁用，并展示后端返回提示。
  - 不创建新的 Jenkins task，不触发新的 Jenkins build。

  - 真实 5174 用例通过并生成截图证据。
  - 本地 Jenkins 必须具备可构建的 API 凭据或运行时验收 token；触发类请求不允许返回 503、404、422 或按钮无动作。
  - 真实环境如已存在同模块活跃重试任务，允许后端 409 拦截，但前端必须展示 `已经有正在的本模块用例`。
