Jenkins daily full module hang diagnosis - 2026-07-06

Scope:
- Job: AiApiTest-DWP-Daily-Full-Module
- Build: #3
- Symptom: Run API Tests stage stayed running after pytest work had finished.

Console access:
- Direct shell request to http://localhost:8080/job/AiApiTest-DWP-Daily-Full-Module/3/consoleText returned 403 Forbidden because shell has no Jenkins browser login session.
- Diagnosis used Jenkins container build log and process table instead.

Build log excerpt:
- + .venv/bin/python -m tools.ci_runner --from-jenkins-env
- Starting web server...
- Can not open browser because this capability is not supported on your platform.
- Server started at http://127.0.0.1:<dynamic-port>. Press <Ctrl+C> to exit

Process evidence:
- The running ci_runner process had a child Java process executing:
  io.qameta.allure.CommandLine open <workspace>/api-test/runtime/ci-runs/jenkins-AiApiTest-DWP-Daily-Full-Module-3/allure-report

Root cause:
- Jenkins passed OPEN_REPORT=true into api-test/tools/ci_runner.py.
- ci_runner treated Jenkins OPEN_REPORT=true as request.open_report=True.
- _generate_allure_report() executed allure open after generating static HTML.
- allure open starts a long-lived web server and waits for Ctrl+C, which blocks non-interactive Jenkins Pipeline execution.

Immediate runtime action:
- The stale allure open process was terminated in the Jenkins container.
- No tools.ci_runner or allure.CommandLine process remained afterward.
- Build #3 became ABORTED because it had already been interrupted from the stuck state.

Permanent fix under test:
- Jenkins Pipeline must force OPEN_REPORT=false in CI.
- ci_runner must ignore OPEN_REPORT=true in Jenkins env mode.
- Local CLI --open-report remains available for developer-only manual runs.
